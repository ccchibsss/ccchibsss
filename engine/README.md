# UC PyEngine — локальный движок UNIT·CONTROL (Python + SQLite)

## Запуск

- **Разработческий**: `run_engine.bat` или `python uc_engine.py serve`
- **Для пользователя (без установки Python)** — два варианта:
  1. `package_portable.bat` → папка **UC-portable**: внутри лежит портативный
     Python (embeddable), пользователь распаковывает и запускает
     `UNIT CONTROL.bat`. Устанавливать не нужно ничего.
  2. `build_exe.bat` → один `UC-движок.exe` (Python вшит в файл).
  Слушает только `127.0.0.1:8765`. Сам интерпретатор Python для движка нужен
  всегда — вопрос лишь в том, что конечный пользователь его не устанавливает:
  он приезжает внутри папки/exe.
- **Планировщик**: `python uc_engine.py watch` — каждые 5 минут: папка
  `engine_data/inbox` → почта → очередь отправки; в 03:00 — бэкап базы.

Токен доступа создаётся в `engine_data/token.txt` — вставьте его в приложение
(раздел «Данные» → Python-движок) один раз.

## Команды

| Команда | Что делает |
|---|---|
| `serve` | HTTP API для приложения: /health, /calc/batch, /import/rows, /import/file, /catalog/recalc, /catalog/results, /catalog/products, /catalog/enrich, /report/dashboard, /export/catalog.xlsx, /export/catalog.csv, /outbox, /outbox/process, /mail/check, /folder/check, /backup, /report/summary, /search |
| `watch` | Цикл: импорт из папки и почты, отправка очереди, ночной бэкап |
| `mail` | Одна проверка почты (IMAP) |
| `folder` | Один проход по `engine_data/inbox` |
| `outbox` | Одна обработка очереди отправки |
| `backup` | Снимок базы в engine_data/backups (хранятся 14) |
| `calc` | Самопроверка экономики на демо-строке эталона |

## Настройки (переменные окружения или engine_data/secrets.json)

- Почта: `UC_IMAP_HOST`, `UC_IMAP_USER`, `UC_MAIL_PASSWORD` (пароль приложения!)
- Ozon: `UC_OZON_CLIENT_ID`, `UC_OZON_API_KEY`; WB: `UC_WB_TOKEN`; ЯМ: `UC_YM_TOKEN`
- На Windows секреты рекомендуется держать не в файле, а выдавать движку через
  переменные окружения/DPAPI-обёртку запуска.

**Безопасность отправки**: настройка `dry_run=1` (по умолчанию) — очередь только
журналируется, реальные запросы на площадки не уходят. Боевой режим включается
осознанно: `POST /settings {"settings":{"dry_run":"0"}}` + заданные ключи.

## Тесты

`python -m unittest discover -s engine/tests` — паритет экономики с золотыми
CSV приложения, налоги, WB, импорт/FTS-поиск, идемпотентность очереди.

## Что ещё даёт Python (реализовано или следующий шаг)

Реализовано: SQLite-каталог с FTS5-поиском, импорт CSV/XLSX/ZIP из почты и папки,
экономика с решателем, очередь отправки с идемпотентностью и журналом, бэкапы,
SQL-отчёт. Естественные следующие шаги: ночные автоотчёты Excel на почту,
мониторинг цен конкурентов по расписанию, сверка остатков с учётной системой
по папке обмена и алерты при ошибках отправок.


## Один Python-файл движка

Весь рабочий код движка объединён в `uc_engine.py` (29 прежних файлов).
Отдельные Python-модули больше не нужны и удалены. Внутри файла раздел
`_BUNDLED_SOURCES` содержит исходники внутренних модулей; встроенный загрузчик
сохраняет их отдельные пространства имён и ленивые импорты, без распаковки
исходников на диск. Для изменения логики редактируйте соответствующий блок
в этом же файле. В строковых блоках обратные слэши экранированы.

Запуск остался прежним: `python uc_engine.py serve`.
Для доступа к внутреннему модулю из внешнего Python-кода сначала выполните
`import uc_engine`, затем, например, `from price_solver import solve_integer`.
Тесты остаются в `tests/` и проверяются командой
`python -m unittest discover -s engine/tests -q` из корня репозитория.

JSON-справочники (`ozon_template.json`, `std_dims.json`,
`csv_kind_rewrites.json`, `ozon_name_expansions.json`) остаются отдельными
файлами данных рядом с движком. Это не Python-модули. База, токен и прочие
пользовательские данные по-прежнему находятся в `engine_data`.
Исторический эксперимент из `tools/python_sqlite_poc.py` также перенесён
в этот файл и доступен только по явной команде `python uc_engine.py poc`.
Он использует демонстрационные CSV из корня репозитория и создаёт/пересоздаёт
отдельную `poc_catalog.db` рядом с движком; производственную БД не трогает.
Отдельного Python-скрипта в `tools/` больше нет. Тесты остаются отдельно.

## Переключение браузер / SQL и хранение каталога

Кнопка режима в приложении теперь показывает также хранилище:

- **Браузер · каталог в IndexedDB** — существующий локальный контур.
- **SQL · каталог в SQLite** — полный снимок строк и основных настроек/правил
  сохраняется через `/app/catalog` в SQLite. Запись товаров в IndexedDB из
  `persistNow` не выполняется, при запуске каталог читается с движка.

Переключение переносит текущий каталог в целевое хранилище; замена существующей
копии требует подтверждения. Режим меняется после успешной записи. Старое
хранилище не очищается. При первом запуске старой установки с уже выбранным SQL
предлагается однократный перенос браузерного каталога. Если движок недоступен,
ошибка не вызывает автоматический браузерный расчёт или сохранение товаров.
После ошибки запуска можно явно открыть прежний браузерный каталог кнопкой режима.

SQL-запись состоит из загрузки частей и атомарной публикации версии. Незавершённая
загрузка не заменяет опубликованный каталог; конкурирующая запись отклоняется по
ревизии. JSON-sidecar сохраняет Date и неограниченные числовые значения в снимке.
Таблицы `app_catalog_*` хранят полные строки приложения, а обычные `products` и
`eco_results` остаются рабочими таблицами независимого расчётного движка.

В SQL-режиме кнопка дискового браузерного импорта открывает обычный импорт с
последующим SQL-сохранением, чтобы обойти прямую запись `products_stage` в IndexedDB.
Прайс и справочники в этом режиме импортируются последовательно.

Ограничения: интерфейс и рабочая копия строк остаются в памяти браузера.
Вспомогательные реестры HVC пока загружаются из прежнего локального хранилища;
это изменение не переносит ВСЕ браузерные реестры в SQLite. Исторические различия
отдельных вычислительных/экспортных операций из parity audit этим не закрываются.
Для больших метаданных действует предел JSON-запроса 50 МБ; данные строк передаются
частями по 1000. Windows/UI E2E на полном пользовательском каталоге не проверены.

### Переключатели настроек в интерфейсе

Выбор браузер/SQL оформлен нативным `checkbox` с `role="switch"`, подписями
обоих режимов и отдельным индикатором хранилища. Во время переноса он отключён;
отмена или ошибка возвращает фактическое состояние. Обычные логические настройки
импорта, автообогащения, ОВХ и экспорта используют тот же Switch. Существующие
идентификаторы и обработчики настроек сохранены. Поддерживаются клавиатура,
видимый фокус, disabled и reduced motion. Выбор строк и согласие на отправку
остаются обычными checkbox; разовые действия (импорт, экспорт, токен) — кнопками.
