# Повторная ошибка «Прайс не сохранён: [object Object]»

## Что подтверждено

До исправления String(error.message || error.name || error) терял причину,
когда message был объектом, либо ошибка приходила как DOM Event с target.error.
То же происходило при new Error(j.error) для структурированного JSON API.
Кроме того, boot-error ветка persistImportOrThrow отдельно склеивала объект
с текстом, и импорт мог уже изменить каталог до отказа по bootReady/bootError.

Введён storageErrorText: вложенные message/error/detail/reason/inner/cause,
DOM target.error, Dexie failures/failuresByPos/errors. Есть защита от циклов,
throwing getters и ограничения глубины/длины. Произвольные данные строк и
настройки не сериализуются в сообщение. Для объекта без известной структуры
показываются только имена полей вместо бесполезного [object Object].

API-ошибка включает HTTP-статус и маршрут. Browser persist сохраняет этап
и сообщение в S._lastPersistFailure. При boot failure импорт останавливается
до upsert строк. Отказ сохранения по-прежнему НЕ считается успехом, входной
буфер не очищается, автоматического удаления/пересоздания БД нет.

## Что НЕ установлено

По скриншоту нельзя определить первичную ошибку хранилища на устройстве:
квота, повреждение БД, конфликт вкладок, отказ SQL API или другой сбой.
Предыдущий код уже уничтожил эту информацию при строковом преобразовании.
Для установления причины нужен исходный browser console error либо новое
подробное сообщение из исправленной версии. Файл пользователя не предоставлен.
Не следует закрывать вкладку с несохранёнными данными до экспорта.

## Причина установлена по присланному журналу

В журнале пользователя первая значимая ошибка — loadSqlCatalog:
«В SQLite нет сохранённого каталога. Откройте браузерный режим и перенесите
каталог кнопкой режима». Установка имела выбранный SQL-режим, но ещё не имела
canonical app_catalog и непустого браузерного каталога для миграции.
Загрузчик считал такое состояние ошибкой, прерывал boot; глобальный catch
сохранял `_bootError` как объект `{name,message}` и оставлял `_bootReady=false`.
Последующий импорт уже изменял строки, но persistImportOrThrow отклонял
сохранение по boot-guard и склеивал объект с текстом — отсюда [object Object].
Это не доказательство нехватки места и не ошибка Cloudflare. 401 для rum,
favicon и source maps не породили показанную loadSqlCatalog-ошибку.

Исправлено: отсутствие SQL-каталога при пустом браузерном каталоге и пустых
строках вкладки — допустимый первый запуск. Пустой ответ проходит обычную
гидратацию, сохраняется ожидаемая revision, настройки не стираются; первый
импорт создаёт durable SQL-каталог. На этапе гидратации пустой каталог не
публикуется. Непустые строки в памяти не затираются: нужен явный перенос.
Миграция непустого browser-каталога по-прежнему требует согласия. Ошибки сети,
auth и чтения не превращаются в пустой успешный запуск.

`tests/sql-first-run-client.js`: first boot, первый save, защита строк памяти,
отказ/согласие миграции, HTTP 401. Suite: **229 tests, 48.179 s, OK**.
