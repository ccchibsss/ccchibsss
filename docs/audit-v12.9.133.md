Дата: 2026-11-08. База: main после PR #63 (клиент 12.9.132, движок 12.9.131).
Проверено прогонами: тесты движка 46/46 OK, тесты приложения OK (золотые 12 SKU),

## Критичные / высокие

### A1. Нет проверки заголовка Host у движка — возможен DNS-rebinding
`engine/uc_engine.py`, класс Handler: токен вшивается в страницу (`render_app_html`,
стр. 1309–1320), а обработчики не проверяют `Host`. Вредоносный сайт может через
DNS-rebinding заставить браузер открыть `http://127.0.0.1:8765/` «со своего» адреса,
прочитать вшитый токен и получить полный доступ к API каталога. Усугубляет
`Access-Control-Allow-Origin: *` (стр. 1337, 1352) — для file-режима клиента он
нужен, поэтому лечение не в CORS, а в проверке Host: принимать только
`127.0.0.1:<порт>` и `localhost:<порт>` в do_GET/do_POST/do_OPTIONS (403 иначе).

### A2. Явный объём товара теряется при синхронизации в SQLite (подтверждено)
`import_rows` (стр. 321, INSERT стр. 328): колонки `volume` в списке вставки нет.
Эксперимент: импорт строки `{volume: 2.5}` без габаритов → в БД `volume = 0.0`,
расчёт движка получает объём 0. Итог: у SKU, где объём задан только числом
(а габаритов нет), движок занижает объёмно-зависимые расходы (логистика/хранение),
а общий экспорт движка выгружает пустой объём. Лечение: добавить `volume` в INSERT
и в ON CONFLICT (`CASE WHEN excluded.volume>0 ...`), плюс регрессионный тест.

## Средние

### A3. Пароли почты хранятся в engine_data/secrets.json открытым текстом
`secrets()` (стр. 247). В README DPAPI-обёртка только рекомендована, не реализована.
Любой процесс/бэкап с доступом к папке получает пароли IMAP. Лечение: DPAPI на
Windows (ctypes CryptProtectData) или хотя бы ACL-предупреждение при сохранении.

### A4. Движок перечитывает и пересобирает index.html на каждый запрос страницы
`render_app_html()` читает 6,9 МБ и вырезает SheetJS при каждом `/` (кэшируется
только сам байт-код библиотеки как побочный эффект). Лечение: кэш по mtime файла.

### A5. Нет лимита на размер тела запроса
`_body()` (стр. 1360) и чтение файла разбора (стр. ~1495, ~1504) читают ровно
Content-Length без потолка — локальный процесс может положить движок гигантским
телом. Лечение: потолок (например, 200 МБ для файлов, 50 МБ для JSON) + 413.

### A6. Две расходящиеся синхронизации каталога в клиенте
`PyEngine._syncCatalog()` шлёт ~30 полей, а `PyEngine.recalcAndApply()` — узкий
набор (нет category/tnved/applicability и остальных атрибутов Ozon). Пересчёт сам
по себе атрибуты не затирает (ON CONFLICT сохраняет непустые), но движок может
считать/выгружать по устаревшим атрибутам, если до этого была только узкая
синхронизация. Лечение: recalcAndApply переиспользует _syncCatalog.

## Низкие

### A7. Сравнение токена не константное по времени; токен перечитывается с диска на каждый запрос
`_auth()` (стр. 1358), `get_token()` (стр. 1322). Лечение: `hmac.compare_digest` +
кэш токена в памяти (файл — только источник при старте/ротации).

### A8. file-режим: токен в localStorage браузера
При открытии index.html файлом токен хранится в localStorage (`uc.pyToken`) —
доступен любому скрипту страницы. Встроенные библиотеки локальные, внешних
скриптов нет, экранирование (`esc()`, 340+ вызовов) — широкое; риск принят
осознанно, фиксируется как известное ограничение.
