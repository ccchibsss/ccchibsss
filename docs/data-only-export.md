# Экспорт загруженных и обогащённых данных

Раздел «Экспорт» → вкладка «Загруженные и обогащённые данные».

- XLSX и CSV UTF-8 с BOM; все строки текущего каталога, в том числе скрытые и исключённые. Фильтры таблицы и ограничения готовности маркетплейсов не применяются.
- Стандартные импортируемые поля STD, если они представлены в каталоге, и все пользовательские колонки (включая обнаруженные в custom без записи в реестре). Пустые зарегистрированные пользовательские колонки сохраняются.
- Значения после маппинга и обогащения, а не исходная структура/названия каждого загруженного файла. Пользовательские заголовки дополнены ключом для различения одноимённых колонок.
- Сохранённые цены, себестоимость и импортируемые ставки — исходные данные, они включены. Производные показатели экономики, формулы, кэши и внутренние метаданные не включаются.
- Нет вызовов ensureEconomics, recalc, Ozon typing, подстановки стандартных габаритов или проверок готовности площадки. Размеры — сохранённые см, вес — кг. Каталог и история импортов не изменяются, кроме обычного сохранения текущего состояния перед SQL-выгрузкой.

В браузерном режиме файл создаётся из текущих строк порциями по 1000. В SQL-режиме сначала сохраняется канонический каталог, затем Python `/export/data-only.csv` или `.xlsx` фиксирует проекцию app_catalog_head/chunks во временный файл в согласованной read-транзакции. После этого read-транзакция завершается: форматирование и скачивание не удерживают WAL. Формирование CSV и XML внутри XLSX идёт порциями, без полного rows/XML в памяти. Ответ передаётся с диска блоками, без полной gzip-копии. Переданная клиентом ревизия проверяется. Таблицы products/eco_results не используются. Ошибка SQL не вызывает браузерный расчёт или fallback.

CSV экранирует кавычки/разделители и нейтрализует формульные префиксы. В XLSX строки записываются как текст, без формул: ведущие нули в строковых артикулах сохранены. Объектные пользовательские значения представлены JSON.

Если браузер поддерживает File System Access API, пользователь выбирает файл при нажатии кнопки: SQL response.body передаётся прямо в writable stream, а браузерный CSV пишется порциями. При отсутствии API остаётся обычное Blob-скачивание (это только транспортная совместимость, не перенос SQL-расчётов в браузер). Отмена выбора файла ничего не сохраняет/не запускает. Ошибка записи прерывает writable. В браузерном XLSX больше нет дополнительной полной матрицы, но worksheet и итоговый ZIP SheetJS остаются в памяти. Между пакетами браузерного экспорта есть yield/проверка отмены и версии каталога.

Ограничения: выгрузка не восстанавливает поля, отброшенные ранее при импорте. XLSX ограничен 1 048 575 строками данных и 16 384 колонками; при превышении нужно выбрать CSV. Нужен свободный временный диск для snapshot и результата. В HTTP нет долговечных export jobs: временные файлы принадлежат одному запросу и закрываются при завершении/ошибке. Генерация ограничена двумя одновременными операциями. Совместимый прямой Python helper export_data_only по-прежнему возвращает bytes; потоковый HTTP его не использует. Windows/браузерный E2E с файлом пользователя не выполнялся.

Проверки: 260 Python tests OK (48.384 s), node tests/run-tests.js OK, 6 inline scripts syntax OK, git diff --check. Новые проверки охватывают оба клиентских режима, чтение канонического SQLite, включение скрытых строк/пользовательских полей, отсутствие экономики/формул, защиту CSV и строковые артикулы с ведущими нулями.

Для использования обновить index.html и Python engine вместе и перезапустить engine. Сброс базы не нужен.
