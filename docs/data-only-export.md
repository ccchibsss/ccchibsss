# Экспорт загруженных и обогащённых данных

Раздел «Экспорт» → вкладка «Загруженные и обогащённые данные».

- XLSX и CSV UTF-8 с BOM; все строки текущего каталога, в том числе скрытые и исключённые. Фильтры таблицы и ограничения готовности маркетплейсов не применяются.
- Стандартные импортируемые поля STD, если они представлены в каталоге, и все пользовательские колонки (включая обнаруженные в custom без записи в реестре). Пустые зарегистрированные пользовательские колонки сохраняются.
- Значения после маппинга и обогащения, а не исходная структура/названия каждого загруженного файла. Пользовательские заголовки дополнены ключом для различения одноимённых колонок.
- Сохранённые цены, себестоимость и импортируемые ставки — исходные данные, они включены. Производные показатели экономики, формулы, кэши и внутренние метаданные не включаются.
- Нет вызовов ensureEconomics, recalc, Ozon typing, подстановки стандартных габаритов или проверок готовности площадки. Размеры — сохранённые см, вес — кг. Каталог и история импортов не изменяются, кроме обычного сохранения текущего состояния перед SQL-выгрузкой.

В браузерном режиме файл создаётся из текущих строк. В SQL-режиме сначала сохраняется канонический каталог, затем Python `/export/data-only.csv` или `.xlsx` читает app_catalog_head/chunks в согласованной read-транзакции. Таблицы products/eco_results не используются. Ошибка SQL не вызывает браузерный fallback.

CSV экранирует кавычки/разделители и нейтрализует формульные префиксы. В XLSX строки записываются как текст, без формул: ведущие нули в строковых артикулах сохранены. Объектные пользовательские значения представлены JSON.

Ограничения: выгрузка не восстанавливает поля, отброшенные ранее при импорте. XLSX ограничен 1 048 575 строками данных и 16 384 колонками; при превышении нужно выбрать CSV. Выгрузка больших XLSX требует памяти: используется существующий писатель Python/SheetJS, это не потоковый XLSX. Python сейчас декодирует канонические строки в память и для CSV. Большой файл пользователя/Windows EXE в этой среде не проверялся.

Проверки: 260 Python tests OK (48.384 s), node tests/run-tests.js OK, 6 inline scripts syntax OK, git diff --check. Новые проверки охватывают оба клиентских режима, чтение канонического SQLite, включение скрытых строк/пользовательских полей, отсутствие экономики/формул, защиту CSV и строковые артикулы с ведущими нулями.

Для использования обновить index.html и Python engine вместе и перезапустить engine. Сброс базы не нужен.
