# Кнопка «Подставить стандартные ОВХ»: запись в каталог

> **Статус: реализовано** в `12.9.176-std-dims-apply-button`.
> Кнопка в разделе «Детектор аномалий габаритов и веса» и кнопки окна
> «Стандартные ОВХ» теперь пишут значения в каталог, а не только при выгрузке.

## 0. Короткий ответ

До этой версии стандартные весогабариты подставлялись **только в момент
выгрузки**: `exportDimsFor()` подставляет справочник и помечает `stdFields`.
В каталог они не попадали намеренно — `StdDims.fill()` начинается с `return [];`
(v12.9.67). Из-за этого кнопки «Исправить отмеченные» и «Заполнить однозначные»
в окне стандартов упирались в сообщение «В каталог не записываем», а SKU с
мусором в весогабаритах навсегда оставались в карантине.

Теперь есть отдельный путь записи (`StdDimsApply`), который:

1. показывает **предпросмотр до записи** — артикул, что сейчас, что станет и что
   будет после проверки пределов;
2. пишет **только точные совпадения** со справочником и помечает источник;
3. где совпадения нет — **медиана по категории**, но только при трёх и более уже
   проверенных SKU той же категории, и такие значения помечаются как «не измерено»;
4. после записи **перепроверяет карантин** по изменённым строкам.

`StdDims.fill()` оставлен отключённым: на нём держится режим «только при
выгрузке», и включать его вслепую нельзя.

## 1. Решение владельца

Из четырёх предложенных вариантов выбран один: **кнопка «Подставить
стандартные ОВХ»** в разделе аномалий. Режимы, согласованные заранее:

| Режим | Как сделано |
|---|---|
| только отмеченные, иначе все заблокированные | `scope()`: есть галочки — берём их, иначе `blockedRows()` |
| писать в каталог с отметкой источника | `_sources[field].stdSubstituted = true` + `_stdDimsApplied` |
| для неоднозначных — средние по категории | медиана по каталогу, при ≥ 3 проверенных SKU категории |
| такие строки выходят из карантина с отметкой | `estimated: true`, красная заливка, «не измерено» в качестве данных |

## 2. Что важно знать про справочник

Поле `c` в `STD_DIMS` — это **название товара**, а не категория: 1782 уникальных
названия, ни одной категории с тремя и более записями. Поэтому медиана «по
справочнику» невозможна в принципе; опорой служат строки каталога той же
категории, которые уже прошли проверку (не в карантине). Меньше трёх — медианы
нет, строка остаётся в карантине: догадку не подставляем.

Вторая особенность: часть названий в справочнике повторяется с разными
габаритами. `StdDims.match()` справедливо возвращает `ambiguous`, и такие строки
в план не попадают — выбирать вариант за владельца нельзя.

## 3. Проверки

Стенд — реальный Chromium (playwright-core + @sparticuz/chromium), каталог
подставлялся в память, справочник — встроенный.

| Проверка | Результат |
|---|---|
| 120 SKU с мусором (41 014) в весе и габаритах | план: 120 точных, 0 медианы, 20 без данных |
| значения после подстановки | совпали со справочником до знака (`55 / 65×55×45`) |
| источник в строке | «справочник стандартных ОВХ: Блок цилиндров (чугун)» |
| строка без опоры | не тронута, осталась в карантине |
| медиана по категории (4 здоровых SKU + 3 мусорных) | 22×13×6.5 / 1.35 кг, `estimated: true` |
| опора из 2 строк | медиана не считается (`null`) |
| 5000 строк | план 4979 точных, предпросмотр 52–85 мс, запись значений 471 мс |
| повторное нажатие | 0 изменений, строка байт в байт та же (нет ложной ревизии) |
| отмена диалога | каталог идентичен |
| перезагрузка страницы | значения, отметка и статус карантина сохранились |
| окно «Стандартные ОВХ», «Заполнить однозначные» | было 0 заполнено → стало 30 |

Отдельно проверено, что после подстановки карантин очищается: из 600 строк
осталось 7 — ровно те, для которых справочник молчит. На 5000 строках осталось
56, и у всех проверка показывает реальное нарушение **пределов категории**
(например, 150 см при лимите 120). Это не баг подстановки: колонка «После
проверки» показывает такие строки **до записи**, чтобы предел категории можно
было пересмотреть осознанно.

## 4. Найденные по ходу ошибки

1. **`finishQuarantine()` не пересобирает флаги строк**, только очередь по старым
   флагам. После записи карантин показывал бы уже исправленные SKU до ручного
   «Сканировать». Исправлено: изменённые строки прогоняются через
   `quarantineRow()` перед пересборкой очереди.
2. **Повторное нажатие писало источник с новой датой** даже когда значения не
   менялись — это тот же класс ошибки, что был с `_dimUnitNote` в v12.9.175
   (ложная ревизия каталога при повторном импорте). Исправлено: пишутся только
   фактически изменившиеся поля, остальные попадают в «уже заполнено».
3. **В тексте источника было «медиана по категории (N записей справочника)»** —
   неверно, опора из каталога. Исправлено на «N проверенных SKU этой категории
   в каталоге».

## 5. Что осталось

* Кнопки старого окна «Стандартные ОВХ» переведены на общий механизм, но само
  окно показывает только кандидатов по справочнику — медианы в нём нет.
  Основной вход теперь — кнопка в разделе аномалий.
* Разбор пустой «Вес товара без упаковки» так и не начат: нужно решение
  владельца, не догадываться.
* Строки, которые остаются в карантине из-за пределов категории, стоит разобрать
  отдельно: либо предел категории занижен, либо справочник даёт габарит не той
  комплектации. Автоматически это решать нельзя.
