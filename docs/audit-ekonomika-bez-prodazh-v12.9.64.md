# v12.9.64 — экономика на единицу без продаж за месяц

Владелец: «Продажи за месяц не нужны». Значит приложение не должно ни требовать эту колонку,
ни показывать нули вместо экономики.

## Что было

1. `enrichColumnsText()` добавляла «Продажи, шт/мес» в список отсутствующих столбцов, и каждая
   строка без продаж несла в качестве данных: `ПРОВЕРИТЬ: добавить столбцы — …; Продажи, шт/мес`.
2. `p.margin` и `p.roi` считались только от месячных величин (`netProfit / revenue`,
   `netProfit / cogs`). Без продаж `revenue = cogs = 0`, поэтому обе колонки показывали **0 %**
   у всех 122 930 строк, хотя прибыль единицы (`perUnitNet`) посчитана.

## Что сделано

1. «Продажи, шт/мес» больше не числится отсутствующим столбцом — предупреждение ушло.
2. Без продаж маржа и ROI считаются **на единицу**: `perUnitNet / price` и `perUnitNet / cost`.
   При наличии продаж остаются месячные значения (поведение не изменилось).
3. Те же формулы записаны в выгрузку Excel, чтобы файл и интерфейс не расходились.

## Проверка (400 строк прайса + весогабаритов, ставка Ozon подтверждена, логистика 100 ₽)

```
EL40X260 · PATRON
цена 694,33 · закупка 694,33 · вес 0,75 кг · 26 см
ЧП на 1 ед.        −351,85 ₽
маржа              −50,7 %      (было 0 %)
ROI                −50,7 %      (было 0 %)
цена безубыточности 1 143 ₽ · целевая 1 534 ₽ · цена для API 1 429 ₽
качество данных    «ок»          (было «добавить … Продажи, шт/мес»)
статус             «Готов к отгрузке»
```

Отрицательная прибыль единицы здесь честная: продажная цена равна закупке, а комиссия,
логистика и последняя миля ничем не покрыты. Приложение показывает, по какой цене единица
выходит в ноль (1 143 ₽) и по какой даёт целевую маржу (1 534 ₽).

## Что осталось месячным

`netProfit`, `revenue`, `cogs` и суммы дашборда по-прежнему месячные: без продаж они нулевые.
Прибыль на единицу видна в колонке «ЧП на 1 ед., ₽» (`perUnitNet`), там же безубыточная
и целевая цена — этих данных достаточно, чтобы ставить цену.
