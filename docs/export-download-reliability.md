# Экспорт не выдаёт файл: исправления 12.9.158

Пользовательский лог снова содержит v12.9.156 и отказ streamXlsx по длине OE.
В main после PR94 уже есть проверка OE до ZIP и предложение UTF-8 CSV. Однако
аудит полного пути нажатия кнопки выявил дополнительные зависимости экспорта
от записи IndexedDB. Поэтому исправление не ограничено советом сменить формат.

## Что изменено

- Открытие раздела export, включая старт с этим разделом, больше не запускает
  ensureEconomics автоматически. Расчётные разделы и отдельный расчёт сохранены.
- ensureCatalogSafeBeforeExport теперь только проверяет известные флаги. Нет
  нового persistNow и нет ожидания незавершённого writer. Экспорт из памяти
  доступен при конфликте/квоте/volatile storage; он не снимает конфликт и не
  заменяет дисковую ревизию. После успешной выгрузки есть предупреждение, если
  сохранение каталога не подтверждено.
- В общем экспорте расчёт выполняется, когда выбраны calc/ana/формульные колонки.
  Для входных колонок он не нужен. ensureEconomicsFor для ВСЕГО браузерного
  каталога, как и для подмножества, использует persist:false: ранее полный набор
  уходил в ensureEconomics и интерактивный pipeline с записью каталога.
  SQL-ветка не меняется и по-прежнему требует SQL-движок/сохранение в SQLite.
- Автоснапшот после экспорта пропускается при pending/dirty/conflict/error, чтобы
  спасение данных не зависело от нового обращения к неисправной БД. Ручные
  снапшоты и их проверки/экспорты не удалены.
- Exp.download не отзывает URL через 800 мс. Теперь видна настоящая ссылка для
  повторного ручного скачивания при блокировке автоматической загрузки браузером.
  Ссылка живёт до 10 минут/закрытия; удерживается не более двух последних Blob.
  Это не ограничение размера одного файла или доказательство низкого peak RAM.
- expRun защищён от повторного запуска. Модалка закрывается только при результате
  true; ошибка, пустая выборка или отказ от CSV оставляют её открытой.
- Раздел «Данные без расчётов» также проверяет все текстовые поля до XLSX.write
  и предлагает полный UTF-8 CSV при >32767. Ничего не обрезается; отказ не пишет
  файл. Браузерный XLSX здесь использует Blob без предварительного picker, чтобы
  при переходе на CSV не создавать выбранный пользователем пустой .xlsx.
  Стриминг CSV/SQL через File System Access сохранён. Для Blob-выгрузки здесь
  используется та же видимая ссылка; имя файла UC_data_without_calculations
  ASCII, чтобы не потерять расширение в браузерах/окружениях, заменяющих
  не-ASCII suggestedFilename на `download`.

## Проверки реальным браузером

`tests/browser-export-e2e.js` открывает приложение в Chromium и НАЖИМАЕТ кнопки
UI, получает настоящие download events, читает скачанные байты. Не подменяет
csvAsync/streamXlsx/download успешными заглушками.

Проверен синтетический каталог **122930 строк**:

- CSV: 2347628 байт, проверено число строк и последний артикул;
- XLSX: 2500383 байт, ZIP-книга прочитана встроенным SheetJS; 122931 строка с
  заголовком, проверены ВСЕ 122930 артикулов, включая ведущие нули;
- OE-список 107997 символов: выбранный CSV и XLSX→подтверждение→CSV содержат
  полный нормализованный список, без обрезки;
- ручная ссылка через 1.2 с (после прежнего срока 800 мс) скачивает те же байты;
- отказ от перехода в CSV и искусственная ошибка генерации оставляют модалку
  открытой и кнопку доступной, каталог не очищается;
- values-only XLSX с длинным OE также выдаёт подтверждённый .csv;
- во всех сценариях persistNow заменён неразрешающимся Promise, выставлены
  pending/dirty/conflict/error; **вызовов persistNow — ноль**;
- входной экспорт с pending-экономикой не вызвал ensureEconomicsFor; отдельно
  VM-тест проверяет persist:false для полного/частичного расчётного экспорта.

Это sparse-тест (артикул и OE + стандартный маркер в общем экспорте), не полный
набор всех экономических колонок/настроек пользователя. Исходных файлов и его
OE-графа нет, полная идентичная пользовательская сессия не воспроизведена.
Не измерялись peak RAM и работа с профилем/политикой загрузок конкретного Chrome.

Node, console regression и восемь IndexedDB/probe suites PASS;
Python **264 PASS, 42.404 с**. Браузерный export-тест включён в CI (1000 строк
по умолчанию; локальный полный прогон — EXPORT_ROWS=122930).

## Обновление без потери данных

Лог v12.9.156 не подтверждает загрузку исправленной страницы. После публикации
нужна v12.9.158-client+reliable-downloads. Не очищайте IndexedDB и не обновляйте
вкладку с единственной несохранённой копией. Сначала используйте доступную
выгрузку из памяти/JSONL в разделе хранилища либо сохраните отдельную копию.
После обновления выберите CSV явно либо подтвердите переход при длинном OE.
Если автоматическая загрузка блокируется, нажмите появившуюся ссылку файла.

Cloudflare /cdn-cgi/rum 405 и deprecated API стороннего beacon не являются
XLSX/CSV-ошибками приложения; их endpoint этим PR не исправляется.
