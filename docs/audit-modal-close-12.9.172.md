# Кнопка «Закрыть» в диалоге «Прерванный импорт» — v12.9.172

## Как воспроизведено

Незавершённый импорт (есть контрольная точка `browserApplyCheckpoint`) →
перезагрузка страницы → модалка «Прерванный импорт» → клик по кнопке
**«Закрыть»**. Экран остаётся заблокированным, диалог не закрывается.
Esc при этом работает.

Воспроизведено на реальном Chromium (`tests/browser-import-recover-dialog-e2e.js`),
контрольная точка создаётся настоящим `BrowserApplyCheckpoint.begin()`:

| Состояние | «Закрыть» | Esc |
|---|---|---|
| до исправления | диалог остаётся открыт | закрывает |
| после исправления | закрывает, отмена возвращает `false` | закрывает |

## Причина (по коду и по замеру)

Порядок запуска в `index.html`:

```
window.addEventListener('DOMContentLoaded', () => {
  try { bindAll(); }            // шаг 1
  UI.boot().then(...)           // шаг 2
```

* `UI.boot()` → `loadAll()` (27021) → `BrowserApplyCheckpoint.recover()` (30047)
  показывает `askConfirm('Прерванный импорт', …)`.
* Обработчики крестика/«Закрыть»/фона навешивались в `UI.bind()` (внутри
  `UI.boot()`, уже ПОСЛЕ `await loadAll()`) — строки 27184–27185.
* Значит на момент показа диалога у кнопки `[data-close]` не было `onclick`:
  в браузере `onclickBeforeClick === "null"`, клик ничего не менял, промис
  `askConfirm` оставался неисполненным (в jsdom-пробе — `pending`).
* Esc обрабатывался в `bindAll()` (49521), поэтому он работал и до исправления.

## Исправление

Закрытие модалок вынесено в `bindModalClose()` и вызывается:

1. в `bindAll()` — до чтения данных, то есть до любого диалога запуска;
2. в `UI.bind()` — как подстраховка для элементов, добавленных позже
   (привязка идемпотентна, обработчики не перезаписываются).

Поведение диалога намеренно не менялось: «Закрыть» — это отказ от
автоматического восстановления. `recover()` в этом случае по-прежнему
останавливает запуск, контрольная точка остаётся на диске, пользователь видит
«Запуск не завершён», а восстановление доступно по «Восстановить» после
перезагрузки.

## Чем проверено

* `tests/browser-import-recover-dialog-e2e.js` (добавлен в CI, Chromium):
  настоящая контрольная точка → перезагрузка → «Закрыть» закрывает диалог,
  контрольная точка сохраняется, запуск сообщает о необходимости восстановления;

## Замечание по диагностике

Контрольная точка, записанная вручную как `{owner}` без полей
`counts/storage/pageCounts`, не является валидной: `restoreAtomic()` ожидаемо
падает на `m.value.counts[name]`. Это свойство ручной подделки маркера, а не
дефект приложения — на настоящей контрольной точке (`begin()`) восстановление
проходит и запуск завершается (`S._bootReady = true`).
