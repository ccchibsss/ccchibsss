Метод: тесты (engine 49/49, app OK, золотые 12 SKU), чтение кода, эксперименты
на живом движке. Первый аудит: docs/audit-v12.9.133.md (A1–A7 исправлены, A8 принят).

## Критичные

### B1. Ценовой реимпорт обнуляет остатки, продажи, вес и габариты в SQLite (подтверждено)
`import_rows` (ON CONFLICT): `stock/sales/weight/length/width/height` перезаписываются
безусловно, а числовые поля отсутствующих в файле колонок превращаются в 0 через `num()`.
Эксперимент: полный импорт строки (остаток 50, вес 1,5, габариты 10×10×10), затем
реимпорт только цены → в БД `stock=0, sales=0, weight=0, length=0`. То есть обычный
сценарий «пришёл свежий прайс только с ценами» уничтожает остатки и габариты движка;
дальше движок считает и выгружает по нулям. В файле колонок может не быть вовсе —
`map_header`/CSV-разбор это различают (ключа нет в dict), а вот `/import/rows` от
приложения шлёт все ключи всегда, поэтому лечение двойное:
- в `import_rows`: числовые поля обновлять только при наличии ключа и осмысленном
  значении (как уже сделано для текстовых полей и price/cost с порогом >0);
- явно переданный 0 остатка при этом должен уметь обнулять — нужен признак
  «поле присутствует» (ключ в dict), а не «>0».

### B2. Массовый пересчёт движка (v12.9.132) подменяет точную экономику плоской моделью
`PyEngine.recalcAndApply` применяет к строкам прибыль/маржу из движка, а движок
считает по плоским настройкам (`_settingsSnapshot`: комиссия 14% по умолчанию,
последняя миля 25 ₽ фикс и т.д.), тогда как браузер — по тарифам категорий и схем.
После отложенного пересчёта цифры в таблице могут заметно «прыгнуть» относительно
браузерного расчёта без объяснения пользователю. Лечение на выбор: (а) помечать
такие строки в UI и писать в тост/лог «посчитано движком по плоским ставкам»;
(б) не применять engine-цифры к отображаемым полям, а использовать ensureEconomics
на движке только как быстрый прогрев для экспортов. Рекомендация — (а) + сверка
`checkEconomics` перед первым применением.

## Средние

### B3. ZIP-импорт без лимитов распаковки (zip-bomb)
`files_from_zip`: все `.csv/.xlsx` читаются в память целиком, без лимитов числа
файлов и суммарного распакованного размера. Эксперимент: zip 29 КБ → 30 МБ в памяти
(коэффициент ×1000). Потолок загрузки 200 МБ (A5) от бомбы не спасает. Лечение:
лимиты (например, ≤ 200 файлов, ≤ 500 МБ суммарно, ≤ 200 МБ на файл) и отказ при
превышении; тот же путь используется почтой и папкой inbox.

### B4. db() на каждый запрос: SCHEMA + 3×PRAGMA table_info + commit
`db()` выполняет executescript и проверки миграций при каждом соединении, а
соединение создаётся на каждый HTTP-запрос (и на каждый чанк синхронизации).
На каталоге в сотни тысяч и пакетных операциях это лишние миллисекунды × тысячи
запросов. Лечение: одноразовая инициализация схемы при старте serve() (флаг),
busy_timeout=5000 для устойчивости параллельной записи.

### B5. Неограниченный рост price_history и api_log
`price_history` пишется при каждом реальном изменении цены (это правильно), но
ротации нет; `api_log` растёт от каждой операции. На годах работы — сотни МБ.
Лечение: retention (например, price_history старше 365 дней и api_log старше
90 дней чистятся при старте/бэкапе).

### B6. Настройки с API-токенами площадок хранятся в localStorage открытым текстом
`uc.settings` в localStorage содержит wbApiToken, mmAuthToken, avitoClientSecret,
secret GAS и т.п. (сохраняется в `saveSettings`, index.html ~37195). Класс риска
как A8, но набор секретов шире. Лечение: маскирование в UI уже частично есть;
полное — хранить секреты только в движке (secrets/DPAPI) и не писать в localStorage.

## Низкие

### B7. map_header: подстрочное совпадение алиасов может выбрать не ту колонку
Алиас `код` для article совпадёт с «Штрихкод», если такая колонка встретится раньше
«Артикула»; `sku` совпадёт с подстроками. Лечение: приоритет точного совпадения
заголовка, затем по началу слова, и явный приоритет «артикул» над «штрихкод».

### B8. watch_folder: повторное имя файла в processed может уронить перенос
`shutil.move` в существующий `processed/<имя>` на Windows бросает исключение —
файл останется и будет импортироваться повторно (импорт идемпотентен по ключу,
поэтому вред — только шум и повторная работа). Лечение: суффикс с датой при коллизии.

### B9. Разделитель CSV определяется только по первой строке
Кавычечный CSV с разделителем внутри кавычек в заголовке может определиться неверно.
Лечение: csv.Sniffer с fallback на текущую эвристику.

## Проверено — в порядке
- Параллельная запись 8 потоков × import_rows: ошибок блокировок нет (WAL + короткие транзакции).
- price_history не плодит дубли при повторных синхронизациях без изменения цены (5 синков = 1 запись).
- num(): «1 000,50», проценты и пустые значения разбираются корректно.
- Outbox: dry-run по умолчанию (dry_run != '0'), реальные ключи площадок без секретов не отправляются.
- ZIP-импорт не распаковывает на диск — path traversal через имена архива невозможен (читается только basename в память).
- Налоги движка: паритет с приложением (тесты 404 случая из первого цикла аудитов, регрессий нет).
