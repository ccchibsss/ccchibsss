# v12.9.119 — Инкрементальный пересчёт на движке

Уточнение по факту: в приложении дельта-пересчёт уже существовал
(changedRows, smallDelta, econSkipFresh — v12.9.54–94). Инкрементальности
не было на движке: recalc_catalog каждый раз считал весь каталог и
перезаписывал eco_results целиком. Здесь закрыт именно этот разрыв.

## Что сделано

- eco_results.inputs_hash (миграция для старых баз): SHA-256 от
  расчётных входов строки (price, cost, sales, weight, length, width,
  height, volume) и снимка настроек экономики.
- recalc_catalog(conn, st, force=False): пересчитываются только строки
  с изменившимся хэшем; результаты пишутся upsert-ом; результаты
  удалённых из каталога SKU чистятся. Итоги ответа (profitable,
  avg_profit) считаются по всей таблице — семантика ответа прежняя,
  добавлены поля skipped и total_sku.
- POST /catalog/recalc принимает force:true для полного пересчёта.
- Приложение показывает «N без изменений (инкрементальный пересчёт)»
  в прогрессе пересчёта на движке.

## Замеры (20 тыс. SKU, песочница)

- Полный пересчёт: 1,17 с (все 20 000).
- Повторный без изменений: 0,21 с (пересчитано 0, пропущено 20 000) —
  остаток времени это хэширование входов и агрегаты, не экономика.
- Одна изменённая цена: 0,22 с, пересчитана ровно 1 строка.
