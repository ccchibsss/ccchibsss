# Что ещё можно оптимизировать благодаря Python — аудит v12.9.107 (2026-11-08)

Что уже на движке: экономика Ozon-пересчёта (v12.9.104), импорт файлов
целиком, обогащение по OE (v12.9.105), почта/папка/очередь отправки, FTS-поиск,
бэкапы. Ниже — что осталось тяжёлого в браузере, с замерами движка на
124 000 синтетических SKU (2 ядра песочницы).

## Замеры движка (124 тыс. SKU)

## Кандидаты на перенос (по убыванию отдачи)

### 1. Экспорт XLSX/CSV на движке — отдача высокая, effort средний ✅ СДЕЛАНО v12.9.108 (экспорт каталога; форматные выгрузки Ozon — следующим шагом)
В браузере осталось ~6 мест `XLSX.write` и ~8 мест `XLSX.read` (экспорты
каталога/Ozon, калькулятор, продажи). На 100+ тыс. строк генерация XLSX
вкладкой — это десятки секунд заморозки и сотни МБ heap; движок отдаёт CSV
за 0.3 с, а XLSX через openpyxl пишется потоково (write-only) без загрузки
в память. Схема: приложение шлёт параметры экспорта → движок собирает файл
из SQLite → браузер скачивает по ссылке с тем же токеном.
Нюанс: в portable-сборку надо докладывать openpyxl (сейчас опционален).

### 2. Полное обогащение (Каталог V) на движке — отдача высокая, effort средний/высокий ✅ СДЕЛАНО v12.9.110 (границы паритета — в доке)
На движке пока только OE-обогащение (название/габариты/аналоги). В браузере
при каждом пайплайне крутятся rebuildIndex и enrichOne: категории, ТН ВЭД,
применимость, доноры по Артикул+Бренд, конфликты OE-доноров, кластеры.
Это ручные индексы в памяти вкладки; в SQL те же доноры — JOIN/GROUP BY
(группировка 20 тыс. OE-групп — 2.3 с на 124 тыс.). Переносить аккуратно,
с паритет-тестами на фикстурах HVC: правила «только пустые поля» и
«доноры расходятся — не берём» должны совпасть 1-в-1.

### 3. Агрегаты дашборда и очереди проверки — отдача средняя, effort низкий
Dash.render и генераторы очередей проверки сейчас считают по всем строкам
в JS при каждом открытии. SQL делает это за 0.04–0.13 с на всём каталоге.
Расширить /report/summary: прибыль/маржа по брендам и категориям, аномалии,
дубли, «чего не хватает» счётчики (сейчас — econReadiness по строкам вкладки).

### 4. Многопроцессный пересчёт — отдача средняя, effort низкий/средний ✅ СДЕЛАНО v12.9.109
calc_row чистый и параллелится: multiprocessing.Pool по чанкам, запись
результатов одним процессом. На 2 ядрах ×1.9, на типичном ПК ×3–5 —
пересчёт 124 тыс. упадёт с ~23 с до ~5–8 с. Осторожно с PyInstaller
(--windowed + spawn на Windows: нужен freeze_support и ленивый Pool
только на время пересчёта).

### 5. Остальные импорты через движок — отдача средняя, effort средний ✅ СДЕЛАНО v12.9.111 (механика + импорт конкурентов; остальные подключаются по одному)
XLSX.read в браузере остался в импортах продаж, заказов, тарифов и
справочников. Обобщить /import/file: движок разбирает любой файл и отдаёт
строки постранично (как /catalog/products), приложение применяет по своим
правилам. Разбор XLSX перестанет зависеть от SheetJS во вкладке.

### 6. История цен и снапшоты — не скорость, а новая возможность ✅ СДЕЛАНО v12.9.112
Движок уже видит каждый импорт: таблица price_history (артикул, бренд,
цена, себестоимость, ts, источник) пишется триггером/вставкой за ~0 мс на
строку. Отчёты «что подорожало за неделю», диффы снапшотов каталога —
SQL-запросы. В браузере это хранить и сравнивать дорого.

### 7. Fuzzy-подсказки аналогов — отдача низкая, effort низкий ✅ СДЕЛАНО v12.9.113
Подбор похожих артикулов (опечатки) блокированием по нормализованному
префиксу + difflib в движке. Правило неизменно: только подсказки оператору
в очередь проверки, никакого автопоиска аналогов (запрет v12.9.85).

## Что переносить НЕ надо

- Рендер таблицы, фильтры экрана, Dexie, What-If по одной строке — данные
  уже на экране, выигрыша нет, а задержка HTTP только вредит.
- GAS-бэкенд — это сервер Google, Python его не заменяет.
- Интерактивная проверка расчёта одной SKU — текущий /calc/batch достаточен.

## Рекомендуемый порядок

1 → 3 → 4 → 2 → 5 → 6 → 7. Первый шаг (экспорт на движке) снимает самую
заметную боль — заморозку вкладки на больших выгрузках; третий дёшев;
второй — самый большой, его делать с паритет-тестами последним из крупных.
