# v12.9.111 — Прочие импорты через движок (обобщённый разбор файлов)

Пункт 5 аудита оптимизаций (docs/python-optimizacii-v12.9.107.md).

## Что сделано

- Движок: `parse_file_bytes` — файл разбирается в кэш (таблицы
  parse_sessions/parse_rows), каталог НЕ трогается. CSV — stdlib
  (UTF-8/cp1251, разделители `; , \t`), XLSX — openpyxl если есть,
  ZIP — первый файл внутри. Хранятся 5 последних разборов.
- Эндпоинты: `POST /parse/file` (бинарно, X-Filename) →
  {parse_id, headers, total}; `GET /parse/rows?parse_id&offset&limit` —
  постраничные строки-объекты по заголовкам файла.
- Приложение: `PyEngine.parseFile(f)` возвращает все строки файла.
  Первый потребитель — импорт цен конкурентов: сначала движок, при
  любой ошибке — прежний браузерный разбор (SheetJS/UC_CSV), правила
  применения строк не менялись.

## Зачем так

У каждого прочего импорта (продажи, заказы, тарифы, справочники) свои
правила применения строк, поэтому движку отдан только разбор файла —
самая тяжёлая и общая часть. Подключение остальных импортов — заменой
источника строк на PyEngine.parseFile с тем же откатом, по одному.

## Проверки

- unittest TestParseFile: CSV-разбор, заголовки, постраничность кэша,
  cp1251+tab, каталог не тронут. Движок 24/24, приложение зелёные.
- Живой HTTP-цикл: /parse/file → total=2 → /parse/rows offset=1 вернул
  вторую строку; products пуст.
- XLSX на движке честно требует openpyxl (как и XLSX-импорт каталога
  с v12.9.101). В portable его нет — там XLSX продолжит разбирать
  браузер (откат для того и сделан), а CSV/ZIP-c-CSV — движок.
