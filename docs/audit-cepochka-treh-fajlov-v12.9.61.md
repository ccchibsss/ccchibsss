# Цепочка трёх файлов поставщика: прайс → кроссы → весогабариты

Прогон штатным путём импорта (тот же `Import.apply`, что в браузере), в песочнице без IndexedDB.
Настройки: активная площадка OZON, «Цена = закупка» включена.

## Найденные проблемы данных

1. **544 строки с невозможной плотностью** (`density_high`, порог 30 кг/л): например PBK1374 —
   1 × 1 × 8 см при весе 0,81 кг даёт 101 кг/л. Похоже, в файле потерян ноль в габаритах
   (10 × 10 × 8 см даёт нормальную плотность). Такие строки приложение ставит в карантин,
   пока их не подтвердят в разделе «Аномалии».
2. **749 строк `oe_review`** — по одному OE пришли разные габариты из разных источников;
   нужен ручной выбор в «Аномалиях».
3. **Продаж нет ни у одной строки** (0 из 204 455): в файлах нет колонки «Продажи, шт/мес»,
   истории продаж тоже нет. Поэтому выручка, прибыль и маржа «в месяц» = 0, хотя
   безубыточная цена, целевая цена и цена для API посчитаны у 203 144 строк.
4. **125 523 строки без габаритов** — в файле весогабаритов 94 336 артикулов из 204 455;
   остальные ждут своего файла или ручного ввода.

## Что это значит для скорости

Суммарно три файла: 596 с в песочнице (163 + 255 + 178). Из них «пересчёт и запись» — 398 с (67 %),
то есть две трети времени уходит на юнит-экономику, а не на разбор и не на обогащение.
