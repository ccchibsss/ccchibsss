# v12.9.87 — Развитие лёгкого импорта: точечный экспорт, сброс после выгрузки, MemGuard-эвристика

Надстройка над v12.9.86 (`skipEconomics` + `S._econPending` + `ensureEconomics`).

## 1. Экспорт считает только свои строки
- `ensureEconomicsFor(rows)`: если выгрузка — подмножество каталога, экономика
  досчитывается дельта-проходом пайплайна (`changedRows: WeakSet`, `smallDelta`,
  без записи в IndexedDB и без сводного тоста) только по строкам выгрузки.
  Каталог остаётся в лёгком состоянии. Выгрузка всего каталога — полный расчёт.
- Точки: `Exp._runImpl` (после финального отбора строк, до формирования файла)
  и калькулятор Ozon. `Exp.run` полный досчёт больше не делает.
- `refreshRowRefs(rows)`: после упаковки строки заменяются компактными объектами —
  список экспорта перечитывается из каталога по `id` (fallback: артикул+бренд).

## 2. Сброс экономики после экспорта
- `releaseEconomics()`: пачками по 2000 сбрасывает `_c`/`__nv`/`mp`/`_t` строк,
  входные поля не трогаются; ставит `S._econPending = true`, сбрасывает срез и
  версию каталога (дашборд/агрегаты не покажут протухшие цифры).
- `Exp._releaseAfterExport()`: вызывается после скачивания файла (основная и
  Ozon-ветки экспорта, калькулятор Ozon) только при включённом лёгком режиме.
  Эффект: ~1,14 КБ/SKU heap освобождается (~220 МБ на 200 тыс. SKU).

## 3. MemGuard без performance.memory (Firefox/Safari)
- `MemGuard.usedEstMB()`: оценка heap по числу строк и состоянию каталога —
  лёгкий ~0,45 КБ/SKU (с индексами), посчитанный ~1,6 КБ/SKU. На 200 тыс.:
  88 МБ / 313 МБ.
- `MemGuard.check()` при отсутствии `performance.memory` использует эвристику
  с теми же порогами (soft 600 / hard 800 МБ); раньше в этих браузерах MemGuard
  молча отключался.

## Проверка
- `node tests/run-tests.js` — OK (+ ассерты ensureEconomicsFor/refreshRowRefs/
  releaseEconomics/usedEstMB).
- Стенды на настоящих фрагментах: подмножество — дельта и сохранённый флаг;
  весь каталог — полный расчёт; refreshRowRefs перечитывает объекты;
  releaseEconomics обнуляет расчётные поля, сохраняя входные, строка после
  сброса снова считается; эвристика MemGuard — 88/313 МБ на 200 тыс.
