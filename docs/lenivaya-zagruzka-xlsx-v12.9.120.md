# v12.9.120 — Ленивая загрузка XLSX в приложении

Из списка оптимизаций после v12.9.119. Web Worker для экономики не взят:
пайплайн приложения и так чанковый с прогрессом, а движок считает
параллельно; перенос computeEconomics в воркер — большой риск ради
неочевидного выигрыша. Взят измеримый пункт — парсинг при старте.

## Факты

- index.html 6,6 МБ; исполняемые блоки при старте: Dexie 262 КБ,
  XLSX 861 КБ, Chart 201 КБ, fflate 32 КБ, основной скрипт 2,6 МБ.
  XLSX нужен только при импорте/экспорте Excel, но парсился всегда.

## Что сделано

- Блок XLSX переведён в `<script type="text/plain" id="xlsx-lib">`
  (как GAS-бэкенд): браузер его не парсит и не исполняет при старте.
- В основном скрипте — ensureXLSX() и геттер на window.XLSX: первое
  обращение к XLSX.* синхронно выполняет текст блока; все 70+ точек
  использования правок не потребовали. На requestIdleCallback
  библиотека догружается в фоне (таймаут 5 с), чтобы первый импорт
  пользователя обычно уже не ждал.
- Дисковый воркер импорта (_xlsxLibSource ищет блок по тексту
  «xlsx встроен офлайн») работает как раньше — text/plain скрипты
  видны в document.scripts.

## Проверки

- Регрессия в tests/run-tests.js: механизм геттера поднимает настоящий
  SheetJS 0.18.5 из блока в чистом vm-контексте (XLSX.version,
  aoa_to_sheet → sheet_to_csv даёт ожидаемый CSV).
- Существующий тест воркера дискового импорта адаптирован: библиотека
  берётся из text/plain блока, а не по индексу scripts[1].
- Все исполняемые скрипты синтаксически валидны; набор приложения зелёный.

## Не сделано (осознанно)

- Chart (201 КБ) — та же техника применима, но у графиков есть
  непокрытые typeof-проверками места; отдельным шагом с прогоном экранов.
- Web Worker для экономики — см. выше; при появлении жалоб на
  отзывчивость при пересчёте вернуться с замерами.
