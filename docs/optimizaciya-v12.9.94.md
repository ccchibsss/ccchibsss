# v12.9.94 — Пакет оптимизаций после дискового импорта

1. **Дисковый импорт без двойной записи.** Пайплайн после подмены каталога
   больше не пишет каталог второй раз полным проходом: пересчёт идёт с
   `persist: false`, затем строки пишутся одной порцией `bulkPut` по 2 500
   (без черновика и транзакции подмены).
2. **Реестры Каталога V в дисковом импорте.** Каждый пакет прайса по ходу
   записи проходит `HVC.ingest` (OE/кроссы/цены/габариты — как touched-строки
   обычного импорта), в конце — `HVC.save()`. Следующие обогащения видят
   данные этого прайса.
3. **Отмена дискового импорта.** Плавающая кнопка «Отменить загрузку»:
   `_diskAbort` прерывает оба прохода, черновик очищается, каталог не тронут.
4. **catFp не пересчитывается на неизменном каталоге.** Мемоизация по ссылке
   на массив + `catalogVersion`: повторные сохранения не сортируют 124k+
   ключей заново (проверено стендом).
5. **Старт без дедупликации при совпадении отпечатка.** Если fp загруженного
   каталога равен сохранённому при записи — дублей появиться не могло,
   `dedupeCatalog()` при загрузке пропускается.
6. **MemGuard сбрасывает экономику.** При давлении памяти (уровень ≥ 1, не во
   время пайплайна/экспорта, не чаще раза в 2 мин) вызывается
   `releaseEconomics()`: каталог худеет с ~1,6 до ~0,45 КБ/SKU, экономика
   досчитается при экспорте. Раньше сбрасывались только кэши и воркер.
7. **Пропуск пересчёта актуальной экономики.** Полный проход пайплайна не
   вызывает `computeEconomics` по всем SKU, если с прошлого полного расчёта
   не менялись каталог (`catalogVersion`), глобальные параметры
   (`fullRecalcStale`), площадка и режим стандартных ОВХ. Категоризация,
   политики и карантин выполняются; вновь заблокированным экономика
   обнуляется точечно. Повторное нажатие «Пересчёт» на неизменных данных
   становится почти мгновенным.

## Не вошло (сознательно)
- **Экономика в Web Worker**: `computeEconomics` зависит от десятков функций
  и состояния приложения; перенос без тестов паритета цифр рискует деньгами.
  Пункт 7 снимает большую часть боли (повторные пересчёты не нужны), а воркер
  остаётся отдельным проектом с паритетными тестами.
- **Постраничный каталог с диска**: переписывание таблицы/фильтров/дашборда;
  делать при каталогах 300k+ SKU.
