# Браузерные таблицы источников

Обычная загрузка через «Импорт» в браузерном режиме теперь сначала сохраняет
каждый CSV/XLSX/XLS/ODS в отдельный набор строк IndexedDB. Файл после загрузки
не нужен для повторного открытия маппинга. В разделе импорта есть кнопка
**«Таблицы источников»**: открыть маппинг либо удалить только исходную таблицу.
Удаление не отменяет уже внесённые изменения каталога. Исходники не являются
резервной копией: браузер может очистить хранилище, действует дисковая квота.

## Обработка

- Отдельная БД `UC_BrowserImportSources`, таблицы `sources`, `rows`, `keys`, `runs`.
  Строки адресуются составным ключом `[source+pos]`. Исходные значения не
  изменяются при применении маппинга.
- CSV читается блоками 256 КиБ. Перед следующим блоком ожидается запись в
  IndexedDB; транзакции записи — до 1000 строк. Предпросмотр — до 200 строк,
  без разреженного массива размером во весь файл.
- XLSX разбирается во Worker. Главный поток запрашивает очередные <=1000 строк
  только после сохранения предыдущих. **SheetJS всё ещё держит распакованный
  лист в памяти воркера**; это не потоковый XLSX-парсер.
- Перед изменением каталога полный проход по источнику строит временный
  дисковый индекс нормализованных ключей и сигнатур. Конфликт в последнем
  пакете блокирует также первый вариант — произвольного «первого совпадения» нет.
  Проверка бренда и стандартных полей соответствует прежнему массивному пути.
  OE, применимость и пользовательские поля не создают такой конфликт.
- Применение читает по 4000 исходных строк и запрашивает конфликты только для
  текущего пакета. Сам merge/OE-накопление/транзитивное обогащение остаётся прежним.
  Первый прайс загружается без обогащения, следующие файлы обогащают его без
  создания новых SKU; экономика при импорте не рассчитывается.
- Полностью построенный индекс сохраняется для повторного Apply того же
  маппинга. Ключ кеша включает версию алгоритма, режим ключа, заголовки,
  выбранные поля/колонки, виртуальные значения и состав стандартных полей.
  Незавершённый индекс не используется повторно. После успешного построения
  нового индекса старые индексы источника удаляются; удаление источника удаляет
  также его индекс. Исходник остаётся доступным.
  Отмена/ошибка чтения удаляет недописанный источник; если удаление не удалось,
  запись `loading` можно удалить в списке источников. После аварийного закрытия
  вкладки недописанные источники также могут остаться в списке, их нельзя применить.
- Режим SQL не создаёт эти таблицы и не может применять сохранённый браузерный
  источник. SQL-импорт и SQLite-хранилище работают прежним отдельным путём.

## Границы

Это устранение полного массива исходного файла и полного RAM-индекса его
конфликтов, **не полностью дисковый каталог**. `S.rows`, каталог V, индексы
целевого каталога и OE-накопители остаются в RAM. Два CSV по миллиону строк
больше не требуют держать оба полных исходных массива, но миллион уникальных
SKU всё ещё может превысить доступную память браузера. Быстрее по времени
не обещается: добавляется первичная запись и дисковый preflight.

Почтовые вложения, программный `applyRows` и отдельный мастер обновления
прайса не перенесены на эту схему. Для повторяемого браузерного сценария с
несколькими большими файлами используйте обычный «Импорт» и список источников.

## Проверки

`tests/browser-import-sources-indexeddb.js` исполняет поставляемый Dexie с
`fake-indexeddb@6.2.8`: независимые источники, полный хвост за пределами preview,
межпакетные конфликты, точное сравнение preflight с массивным путём в двух
режимах ключа, OE/custom без ложных конфликтов, повторное открытие БД, удаление,
отмена, битый CSV, квота, запрет SQL. Проверяется реальный XLSX worker protocol
на 2503 строках: pull-пакеты, текстовые ведущие нули и последний пакет.

```sh
npm install --prefix .arena/idb-tests fake-indexeddb@6.2.8 --no-save --no-audit --no-fund
NODE_PATH=.arena/idb-tests/node_modules node tests/browser-import-sources-indexeddb.js
```

Тест не является браузерным замером RAM или гарантией обработки 2×1 млн на
конкретном устройстве. Для увеличения синтетического CSV: `SOURCE_ROWS=100000`.

## Дополнительная оптимизация и сериализация операций

Обычное чтение импорта, Apply, удаление источника и переключение browser/SQL
используют единую блокировку. Повторный запуск в одной вкладке отклоняется.
При наличии Web Locks конфликтующая операция в другой вкладке отклоняется
через `ifAvailable`, без скрытой очереди и последующего применения устаревшего
маппинга. Ошибка внутри callback не приводит к повторному выполнению операции.
В браузерах без Web Locks защита ограничена одной вкладкой. Это не глобальная
блокировка всех редакторов каталога, фоновых действий или отдельных мастеров.

Список `touched` теперь содержит каждую изменённую строку не более одного раза,
даже если для неё во входном файле тысячи OE. Финальный список изменений
строится без промежуточного объединённого массива из трёх списков; повторный
Set поверх уже уникального touched убран. Сами правила накопления OE и
транзитивного обогащения не изменены.

**Пока не реализованы:** дисковый целевой каталог вместо `S.rows`, атомарная
публикация всего обогащённого каталога/реестров и восстановление прерванного
Apply. Ошибка/отмена после начала изменения каталога по-прежнему может оставить
частично изменённый каталог в памяти. Сериализация и кеш не дают rollback.
Прогон в настоящем браузере на 2×1 млн строк также пока не выполнен.
