# v12.9.57 — раздел ABC/XYZ удалён

Итерация к v12.9.56 (упаковка строки до расчёта). Задача: убрать раздел ABC/XYZ
целиком, чтобы освободить время пересчёта и память под основной функционал —
юнит-экономику одной выбранной площадки (по умолчанию OZON) и её выгрузку.

## 1. Что удалено

| Место | Удалено |
|---|---|
| Дашборд | карточка «Матрица ABC × XYZ» (`#dbMatrix`), сетка из двух колонок свёрнута в одну |
| Лист «Юнит-экономика» | весь блок «ABC / XYZ — на листе «Юнит-экономика»»: 9 контролов (`axMetric`, `axA`, `axB`, `axX`, `axY`, `axSeries`, `axStatus`, кнопка `axCalc`), матрица `#axMatrix`, два графика (`#chAbc`, `#chXyz`), обработчики параметров и дебаунс пересчёта |
| Код | модуль `ABCXYZ` (~80 строк) — расчёт классов, VX, матрицы 3×3, отрисовка |
| Пайплайн | шаг `prog('расчёт ABC/XYZ…')` и вызов `ABCXYZ.calc()` в `runPipeline`; вызовы в правке карточки товара, подтверждении аномалии, пересчёте тарифов и цен |
| Фильтры | селектор `#fAbc`, поле `f.abc` в состоянии фильтра, в сигнатуре воркера, в чипах активных фильтров, в сбросе |
| Таблица | колонки `abcClass` / `xyzClass` (`TCOLS`, ветка рендера ячеек, обязательные чипы колонок) |
| Данные | теги классов в карточке товара и в строке «Топ/антирейтинг/зона риска» на дашборде, строка «VX (варьируемость)» |
| Экспорт | колонки `ABC`, `XYZ`, `Матрица`, `VX, %` в каталоге выгрузки и их правила условного форматирования XLSX |
| Автозаказ | селекторы «Классы в заказе» и «XYZ», фильтры `abcW`/`xyzW`, упоминание в строке прогресса и в поле `basis` |
| Облако | `abc_class` / `xyz_class` в выгрузке товаров в Google Sheets |
| CSS | сетка матрицы `.mx` (6 правил) — разметки, которая её использовала, больше нет |

Поля `abcClass`, `xyzClass`, `matrix`, `vx`, `xyzZeroDemand` больше не вычисляются.
Строка каталога на первом проходе получает на 5 расчётных полей меньше.

## 2. Что стало с зависимыми местами

| Зависимость | Решение |
|---|---|
| Автозаказ фильтровал по классам | фильтры сняты: заказ строится по всем неисключённым SKU (как если бы были выбраны «A+B+C» / «X+Y+Z») — иначе после удаления фильтр получал `undefined` и заказ был бы всегда пустым |
| `recommend()` — два правила по классам | правила удалены; остались правила по марже, дефициту, отсутствию продаж, нулевому остатку |
| График продаж в карточке товара | ряд берётся из `p.salesSeries`; если его нет — локальная функция `salesSeriesOf(p, mode)` (раньше строил `ABCXYZ.series`) |
| Шаблоны сообщений с `{abc}` | ключ `abc` убран из контекста выражений (было `p.abcClass || 'C'`), в подстановке — пусто |
| Сортировка кандидатов MOQ по классу | сортировка снята (порядок остаётся по релевантности/остаткам) |
| Индекс `abcClass` в схеме IndexedDB | схема **не менялась**: это выпущенная версия БД, её правка уронила бы существующих пользователей на открытии базы. Поле в индексе просто не заполняется |

## 3. Замеры

Стенд: Node 22, клиентский скрипт грузится в песочницу с минимальной DOM-заглушкой,
синтетический каталог автозапчастей, режим «одна площадка — OZON» (по умолчанию),
`runPipeline(true)` с отключённой записью.

### 3.1. Эквивалентность юнит-экономики

Сравнивались все поля строки после пересчёта, кроме удалённых пяти
(`abcClass`, `xyzClass`, `matrix`, `vx`, `xyzZeroDemand`) и служебных (`_t`, `_sources`, `salesSeries`).

| Прогон | Строк | Полей в строке | Различий |
|---|---|---|---|
| OZON, 3 000 | 3 000 | 72 | **0** |
| OZON, 30 000 | 30 000 | 72 | **0** |
| ALL (5 площадок), 3 000 | 3 000 | 71 | **0** |

Суммы совпадают: чистая прибыль 30 000 строк — 738 497 167 ₽ в обеих версиях,
ALL-режим 3 000 строк — 76 883 353 ₽. Строк с оставшимися полями ABC в 12.9.57 — 0.

### 3.2. Стоимость удалённого шага

`ABCXYZ.calc()` на готовом каталоге 30 000 строк: **369 мс** (12,3 мкс/строка).
В браузере пересчёт 30 000 строк занимает ≈4,5 с (148 мкс/строка, замер 12.9.56),
то есть удалённый шаг — порядка **8 % времени пересчёта**. Кроме пайплайна он
вызывался ещё в трёх местах (сохранение карточки, подтверждение аномалии,
пересчёт тарифов) — там он снят целиком.

### 3.3. Полный пересчёт, 30 000 строк, 3 независимых прогона

| Версия | Время (мс) | Мкс/строка | heap после пересчёта |
|---|---|---|---|
| 12.9.56 | 34 352 / 33 608 / 32 542 (медиана **33 608**) | 1 120 | 218 / 220 / 213 МБ (медиана **218**) |
| 12.9.57 | 39 186 / 33 556 / 33 315 (медиана **33 556**) | 1 119 | 212 / 214 / 213 МБ (медиана **213**) |

Разница по времени — в пределах шума (±0,2 %). Причина: в песочнице доля шага ABC
растворяется в общей стоимости (в этом стенде пересчёт идёт ~1,1 мс/строка против
148 мкс в браузере — сказывается отсутствие прогретого JIT браузера и стендовые
накладные). Память: **−5 МБ на 30 000 строк** (≈ −180 Б/строка, −2,5 %), полностью
из памяти ушли пять полей строки.

### 3.4. Точечный пересчёт (дельта)

Изменена себестоимость трёх строк из 2 000 → пересчитано ровно 3 строки, 154 мс,
значения совпали с расчётом «с нуля».

## 5. Ограничения и что учесть

- **Рекомендации**: два правила, опиравшиеся на классы («маржа > 45 % и класс A»,
  «класс Z»), больше не срабатывают. Если они нужны — их можно вернуть на чистой
  марже/обороте без раздела ABC.
- **Автозаказ** теперь охватывает весь каталог, а не выбранные классы: на больших
  каталогах список кандидатов станет больше (фильтр по исключённым остался).
- **Старые данные**: у ранее сохранённых пользователей в строках могут остаться
  `abcClass`/`xyzClass` — приложение их читает как обычные поля и нигде не использует;
  при следующей записи каталога они просто не обновляются.
- Выгрузки, где были колонки ABC/XYZ, стали на 2–4 колонки короче — если внешний
  файл их ждёт, его нужно поправить.
