# v12.9.104 — Полный пересчёт каталога на Python-движке

Следующий шаг локализации: тяжёлый пересчёт уехал из вкладки в движок.

## Поток

1. Кнопка «Python: пересчитать каталог» (раздел «Данные»).
2. Приложение отправляет строки каталога в движок чанками по 5000
   (POST /import/rows, FTS перестраивается один раз в конце).
3. Движок импортирует в SQLite и считает экономику по всем SKU
   (POST /catalog/recalc), результаты — в таблицу eco_results.
4. Приложение забирает результаты постранично (GET /catalog/results)
   и применяет к строкам: прибыль, маржа, ROI, безубыток, целевая цена
   (пометка pyEngineCalc). Вкладка при этом не считает и не зависает.

## Честные границы

- Модель движка сейчас повторяет Ozon-расчёт приложения с паритетом по
  золотым фикстурам; настройки берутся из приложения (комиссия, перевод,
  налог, целевая маржа). Возвраты/хранение задаются настройками движка и
  могут отличаться — поэтому «Python: проверить расчёт» остаётся как
  независимая сверка, а пересчёт помечает строки своим источником.
- Движок выключен — кнопка честно предупреждает, приложение считает
  встроенным расчётом, как раньше. Никакой зависимости от Python нет.

## Проверки

- unittest: recalc_catalog на эталонных строках (прибыль 3394.33, BE 14377).
- Живой HTTP-цикл: импорт чанками → пересчёт → постраничные результаты,
  обе страницы совпали с золотыми CSV.
