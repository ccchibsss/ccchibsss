# Аудит паритета браузер ↔ SQL-движок (v12.9.155)

Требование: все расчёты и обогащения — точно как в браузерной части, исполняет SQL.

## Расчёты (calcMarketplacesEconomics браузера → движок)

| Площадка | Браузер | Движок до аудита | После |
|---|---|---|---|
| Ozon | evaluateOzon | браузерная формула (12.9.146) | без изменений |
| WB | evaluateWb | браузерная формула (12.9.149) | без изменений |
| Яндекс Маркет | evaluateYm + tariffFor | не было (отказ) | ym_unit + построчный тарифный снимок из _syncCatalog (placement/transfer/agency/boost/return/found); нет тарифа — строка не считается, как в браузере |
| Мегамаркет | evaluateMm | не было | mm_unit по формуле браузера |
| Авито | evaluateAvito | не было | avito_unit, incl. минимум 1 ₽ при профи |

Общее: налог — calcTax (паритет всех режимов), кратность закупки, промо-цена
eff_price, невыкуп SKU→категория→общий, месячный фикс / продажи, solver
безубытка/целевой (100% невыкуп → 0/0), excluded/visible не считаются.

Известные пределы ЯМ: quote-ставки кабинета (offer) и сценарии What-If в снимок
не входят — placement берётся из tariffFor строки на момент синхронизации;
per-row поля ММ/Авито (mm_commission и т.п. из custom) в SQL не синхронизируются,
работают ставки настроек.

## Обогащение (HVC браузера → enrich_full/enrich_oe)

Сверено и совпадает: только пустые поля; первый файл — прайс, остальные —
только обогащение (пара, уникальный OE, доноры); нормализация ключей;
карантин спорных идентичностей; категория/ТН ВЭД по паре, по OE — единогласно;
заглушки категорий не значения; габариты цельным комплектом, OE-доноры только
в режимах oe/auto, мера выбора комплекта как DimPolicy; аналоги и
group_articles по OE-группе; barcode/image/multiplicity от донора той же пары;
применимость в enrich_oe.

## Экспорт/импорт/сопоставления

Сверено ранее (12.9.146–154): однозначный маппинг колонок, единицы импорта,
XLSX без openpyxl, экспорт Ozon построчно (партномер, лимиты, ошибки/недочёты),
видимость и исключения в выгрузке и пересчёте, fallback пустой выборки.
