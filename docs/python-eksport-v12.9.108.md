# v12.9.108 — Экспорт каталога на Python-движке

Пункт 1 аудита оптимизаций (docs/python-optimizacii-v12.9.107.md):
генерация файла уехала из вкладки в движок.

## Что сделано

- Движок: `export_catalog_csv_bytes` (UTF-8+BOM или windows-1251) и
  `export_catalog_xlsx_bytes` — XLSX собирается на чистом stdlib
  (zipfile + XML, inline-строки, числа числами). openpyxl НЕ нужен:
  portable-сборка зависимостей не имеет и продолжит работать из коробки.
- Эндпоинты (только с токеном): `GET /export/catalog.xlsx`,
  `GET /export/catalog.csv?enc=utf-8|cp1251`. Колонки каталога +
  экономика из eco_results (LEFT JOIN): прибыль, маржа, ROI, безубыток,
  целевая цена.
- Приложение: кнопка «Python: экспорт каталога». Каталог синхронизируется
  в движок общим `_syncCatalog` (им же теперь пользуется сводка),
  делается свежий пересчёт с настройками приложения, файл скачивается
  blob-ом. Вкладка XLSX не строит и не зависает.
- Движок выключен — кнопка честно предупреждает, обычный экспорт
  приложения работает как раньше.

## Проверки

- unittest: CSV (BOM, заголовки, cp1251) и XLSX (валидный zip, sheet1.xml,
  XML-экранирование `&`, числа как `<v>`). Движок 17/17.
- Живой HTTP-цикл: импорт DEMO-CLT-001 → пересчёт (прибыль 3394.33 —
  золотой эталон) → скачанный XLSX прочитан обратно через openpyxl:
  шапка, строка и прибыль на месте; CSV в cp1251 читается.

## Границы

- Это экспорт каталога движка (20 колонок). Форматные выгрузки приложения
  (шаблон Ozon на 46 полей, калькулятор с формулами) пока строит вкладка;
  их перенос — следующим шагом по мере надобности, механика доставки
  файла уже есть.
