# v12.9.78 — дельта-режим доведён до конца

Модель работы: первый файл — базовый каталог (полный цикл один раз), каждый
следующий — только новые вводные и связанные с ними строки.

## 1. Автосверка аномалий OE — доноры через реестр

`AnomalyOE.find` больше не разбирает OE каждой строки каталога. Доноры
собираются по реестру: связки-держатели нужных OE (`HVC.byOe`) + идентичности
целей + строки со служебными OE-доказательствами импорта. По каталогу остаётся
лёгкий отбор по ключу связки. Логика владельцев, кандидатов и лимитов не
изменилась.

Контроль: функциональный тест на настоящих `AnomalyOE`+`DimPolicy` — донор по
общему OE находится, габариты применяются, строка помечается к проверке.

## 2. Триггер «нужен полный пересчёт»

Отпечаток глобальных параметров экономики (ставки, логистика, налоги,
постоянные расходы, словарь категорий, правила) запоминается при каждом полном
пересчёте (`uc.fullCalcFp`). Если параметры изменились, а работа шла дельтами,
сноска недостающих данных в разделе «Данные» предупреждает: цифры неизменённых
строк могут устареть. Причина честности: доля постоянных расходов на единицу
зависит от числа SKU и дельта-пересчётом старых строк не обновится.

Контроль: тест отпечатка — смена ставки помечает устаревание, смена
неэкономической настройки (URL) — нет.

## 3. Профиль дельты в журнале импорта

В консоль после применения импорта: изменено строк / всего в каталоге / % /
объединено дублей / новых SKU — видно, что обработка идёт только по новым
вводным.
