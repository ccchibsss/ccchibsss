# v12.9.77 — таргетные rebuildIndex, dedupe и запись дельты

Продолжение 12.9.75–12.9.76: три оставшихся полных прохода при импорте
переведены на работу по дельте. Результаты расчёта и состав каталога не меняются.

## 1. Таргетный `HVC.rebuildIndex` при импорте (этап «индекс OE»)

`rebuildIndex(list, onlyKeys)`: при импорте перестраиваются только связки строк
файла. Импорт лишь добавляет/сливает OE, поэтому измениться могут OE-списки
строк затронутых связок и «Группа артикулов» держателей их OE — они добираются
через `HVC.byOe`. Полная перестройка сохранена для загрузки и ручных операций.

Замер настоящим кодом (200 000 строк / 50 000 связок, дельта 100 связок):
**полный 10 520 мс → таргетный 335 мс**.

Контроль: функциональный тест в `tests/run-tests.js` — на OE-графе из 5 строк
(мост через новый OE) таргетная перестройка даёт построчно тот же результат,
что полная (`oe_numbers`, `oe_list`, `oe_norm`, `group_articles`, `groupSize`),
включая обновление групп связанных связок.

## 2. Таргетный `dedupeCatalog`

Полный проход выполняется один раз на новый массив каталога (загрузка,
серверная замена — отслеживается по ссылке `S.rows`), дальше слияние дублей
проверяется только по связкам строк текущего файла: upsert по ключу не может
создать дубли в чужих связках.

Контроль: тест — таргетный проход сливает заданную пару и не трогает чужую,
полный сливает обе.

## 3. Запись только дельты при любой доле изменений

`persistChangedOnly` при импорте больше не ограничен дельтой < 2 %:
записываются только изменённые строки (`changedTouched > 0 && !dedup`).
Полная перезапись остаётся при слиянии дублей (строки удаляются из каталога).
Слияния OE по связкам и группы артикулов загрузка выводит заново из записанных
строк (`rebuildIndex` при старте), поэтому не попавшие в запись производные
значения соседних строк не теряются.
