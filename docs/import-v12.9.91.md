# v12.9.91 — Пересчёт экономики по стандартным ОВХ

## Зачем
У SKU без габаритов логистика считается по пустым значениям. Типовой справочник
стандартных ОВХ (StdDims, 12k+ вариантов) раньше работал только при выгрузке
(exportDimsFor) и в анализ; в расчёт экономики стандарты не попадали, а запись
их в каталог запрещена правилом v12.9.67.

## Что сделано
- Настройка `S.settings.calcStdDims` (переключатель «Пересчёт экономики по
  стандартным ОВХ» в настройках обогащения) и кнопка «Пересчёт по стандартным
  ОВХ» рядом с «Применить весогабариты»: включает настройку и запускает полный
  пересчёт каталога с тостом о числе помеченных SKU.
- `computeEconomics` обёрнут: `stdDimsSubstituteForCalc(p)` перед расчётом
  подставляет типовые значения ТОЛЬКО в пустые поля (length/width/height/weight)
  и ТОЛЬКО при точном совпадении стандарта (категория/вид/название; match
  'contains' и неоднозначные не применяются). После расчёта реальные поля и
  объём восстанавливаются; SKU помечается `_stdDimsCalc {source, fields, at}`.
- Пометка видна в «Качестве данных»: «габариты для расчёта — СТАНДАРТНЫЕ
  (не измерены): …». В IndexedDB пометка не пишется (вырезана в slimOf).
- Заблокированные аномалии не подставляются (карантин важнее).

## Проверка
- Стенд настоящей обёртки: подстановка видна внутри расчёта; после — поля и
  объём восстановлены, пометка стоит; выключенная настройка снимает пометку;
  'contains' не применяется; реальный вес при частичной подстановке не тронут.
- `node tests/run-tests.js` — OK; `node --check` — OK.

## v12.9.92 — Подсветка в выгрузке
SKU, посчитанные по стандартным ОВХ, выгружаются с колонкой «ОВХ из стандартных
при расчёте» (текст «СТАНДАРТ-РАСЧЁТ: <стандарт> (поля)»). В XLSX колонка и
артикул таких строк подсвечиваются #FFA07A условным форматированием главного
листа; в CSV остаётся текст маркера. Помеченные SKU из выгрузки не исключаются.
