# v12.9.55 — расчёт одной выбранной площадки (по умолчанию Ozon)

Итерация к v12.9.54. Цель — ускорить обработку больших каталогов и сделать основным
режимом юнит-экономику **одной выбранной площадки** (по умолчанию Ozon), включая
выгрузку её расчётов для прогноза.

## 1. Что было и что стало

| | было (v12.9.54) | стало (v12.9.55) |
|---|---|---|
| Решатель цен | 5 моделей на каждую строку (`solveMarketplacePrices` × WB/OZON/YM/MM/AVITO) | 1 модель — выбранной площадки, по умолчанию OZON |
| `p.mp` | 5 экономик | 1 экономика |
| Плоские поля (`profitWB`, `beOzon`, …) | заполнены все 25 | заполнены только для посчитанной площадки, остальные `null` (в интерфейсе и выгрузке — «—», не 0) |
| «Лучший МП» / «Разброс ЧП МП» | считались всегда | только в режиме сравнения (`ALL`) |
| Колонки таблицы | 5 площадок | только выбранная (в режиме сравнения — все) |
| Файл выгрузки юнит-экономики | `UC_unit_economics_<дата>.xlsx` | `UC_unit_economics_OZON_<дата>.xlsx` (метка площадки) |

Режим сравнения не удалён: кнопка «Сравнение · KPI ЯМ» в шапке (и `setActiveMarketplace('ALL')`)
возвращает прежнее поведение — считаются все пять моделей.

## 2. Изменения в коде

| Место | Что сделано |
|---|---|
| `S.settings` (строка ~17693) | `activeMarketplace: 'OZON'`, новый флаг `calcSelectedMpOnly: true` |
| `economicsScopeMp()` (перед `calcMarketplacesEconomics`) | область расчёта: `'ALL'` (сравнение) либо код выбранной площадки |
| `calcMarketplacesEconomics` | `needMp(code)` — решатель запускается только для площадки области; `p.mp` собирается из посчитанных; плоские поля через `flatMp()` (null вместо нуля) |
| то же, блок сравнения | при области ≠ `ALL` блок «Лучший МП» не заполняется, `marketComparisonIncomplete = false` (сравнение не запрашивалось, а не «неполные данные») |
| `computeEconomics` | передаёт `calcMeta.scopeMp = economicsScopeMp()` |
| загрузка настроек | сохранённый `ALL` без явного отказа переводится на `OZON` + одноразовое пояснение (`S._mpScopeMigrated`) |
| `setActiveMarketplace` | конкретная площадка → `calcSelectedMpOnly = true`, `ALL` → `false`; пересобираются колонки |
| `buildCols` / `columnMarketplace` | колонки чужих площадок скрыты в режиме одной площадки |
| `Dash.render` | подпись области: «считается одна площадка (сравнение — кнопка «Сравнение» в шапке)» |
| `calcMarketplacesEconomics` (`currentOzonOnly`) | если Ozon не был посчитан пайплайном, безубыток и рекомендованная цена считаются решателем, а не берутся нулями |
| `mpTag()` + выгрузки | метка площадки в имени CSV/XLSX |

Версия: `APP_VERSION = '12.9.55-client+audit.1'`, запись в журнале версий в шапке файла.

## 3. Замеры (Node 22 + fake-indexeddb, синтетический каталог автозапчастей)

### 3.1 Пайплайн пересчёта

| Конфигурация | 30 000 строк | 60 000 строк | мкс/строка (60k) |
|---|---|---|---|
| v12.9.54, выбран Ozon (считались 5 площадок) | 16 167 мс | 28 834 мс | 481 |
| v12.9.55, режим сравнения (`ALL`) | — | 30 567 мс | 509 |
| **v12.9.55, одна площадка (Ozon)** | **5 471 мс** | **10 668 мс** | **178** |

Ускорение — **2,7–2,9×** на всём пайплайне. Остаток времени (~55 %) — работа, не зависящая
от числа площадок: подготовка тарифов, `computeEconomics`, `_formatNumber`, ABC/XYZ, GC.
На 217 448 SKU (реальный каталог клиента) это ≈ 117 с → ≈ 39 с только на этапе пересчёта.

### 3.2 Память

`p.mp` измерен как разница heap после `delete p.mp` у всех строк (30 000 строк, после GC):

| Режим | `p.mp`, Б/строка | ключи |
|---|---|---|
| v12.9.54 (5 площадок) | 2 400 | WB, OZON, YM, MM, AVITO |
| v12.9.55, сравнение | 2 432 | WB, OZON, YM, MM, AVITO |
| **v12.9.55, одна площадка** | **680** | OZON |

Экономия ≈ **1 720 Б/строка**, то есть ≈ **−374 МБ** на каталоге 217 448 SKU.
Общий heap процесса на 30 000 строк: 213 МБ (v12.9.54) → 205 МБ (v12.9.55); разница ниже
расчётной из-за шума GC, поэтому опираться стоит на замер `p.mp`.

## 5. Выгрузка юнит-экономики выбранной площадки

* Имя файла теперь содержит площадку: `UC_unit_economics_OZON_<дата>.xlsx`,
  `UC_economics_OZON_<дата>.csv` (в режиме сравнения — `ALL5`).
* Колонки чужих площадок в выгрузке отключены вместе с переключателем площадок
  (`Exp.activeMps()`), а если поле всё же выбрано вручную — ячейка пустая
  (`marketplaceResultUnavailable`), а не 0. Пустая ячейка честно означает «не считалось».
* Калькулятор Ozon (`OzonExport.generateEconomicsXlsx`, кнопка «Ozon — калькулятор
  юнит-экономики») не зависит от выбранной площадки: он считает Ozon-экономику сам,
  а при отсутствии кэша теперь досчитывает безубыток и рекомендованную цену решателем.
  Проверено: при выбранной WB `be/tgt` непустые (1624 / 2179 ₽ на тестовой строке),
  файл формируется (~12 КБ на 2 строки).
* Формульный калькулятор по-прежнему ограничен 20 000 SKU на файл (не менялось).

## 6. Поведение приложения

* Свежая установка: `activeMarketplace = 'OZON'`, `calcSelectedMpOnly = true`.
* Сохранён `ALL` без нового флага → при запуске переводится на `OZON`, показывается
  пояснение один раз; настройка сохраняется.
* Пользователь явно остался в сравнении (`calcSelectedMpOnly: false`) → остаётся `ALL`.
* Сохранена конкретная площадка (например `WB`) → остаётся `WB`, режим одной площадки.
* Клик по площадке в шапке или по карточке площадки в дашборде пересчитывает каталог
  по выбранной модели; клик по «Сравнение» — по всем пяти.
* Карточки площадок в дашборде для нерассчитанных моделей показывают «нет расчёта»;
  числа прошлых расчётов не выдаются за свежие — при пересчёте строки `p.mp`
  пересобирается заново.

## 7. Ограничения и риски

1. Если каталог **не пересчитывался** после перехода на режим одной площадки, в базе
   остаются `p.mp` прежних пяти моделей. Таблица и выгрузка их не показывают (колонки
   скрыты, `Exp.activeMps()` = одна площадка), но дашборд может показать старые значения
   по четырём площадкам до первого пересчёта. Числа не пересчитываются «на глаз» —
   это те же данные, что были сохранены ранее.
2. Режим сравнения остаётся в ~2,7× дороже по времени и на ~1,7 КБ/строку тяжелее —
   это осознанная плата за пять моделей.
3. Производные тексты в персисте (`tariffQuoteReasons`, `recommendation`,
   `marketComparisonReasons` и др., ~35 % объёма записи) не сокращались — кандидат
   на следующую итерацию.

4. «Сравнение · KPI ЯМ» → каталог пересчитывается по всем пяти, колонки возвращаются,

5. Выгрузка «Юнит-экономика»: имя файла содержит `OZON`, колонки чужих площадок
   отсутствуют, пустых нулей нет.
6. «Ozon — калькулятор юнит-экономики»: файл формируется при любой выбранной площадке,
   колонки «Безубыточность» и «Рекомендуемая цена» заполнены.
