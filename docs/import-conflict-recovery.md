# 12.9.159 — продолжение импорта после конфликта ревизий

## Что подтверждает лог пользователя

В 12.9.158 Apply остановлен в BrowserApplyCheckpoint.begin перед изменением
каталога: persistNow получил CatalogConflictError, затем begin заменил причину
общим сообщением «Не удалось сохранить исходное состояние перед импортом».
Сохранённая ревизия не совпала с загруженной в память. Лог НЕ доказывает, что
прямо сейчас открыта вторая вкладка, и не позволяет определить автора записи.
Повторять Apply или отключать assertCatalogFresh небезопасно. AbortError пробы
IndexedDB и Cloudflare rum 405 — отдельные сообщения, не причина этого отказа.

## Исправление

- begin сначала проверяет ревизию в read-транзакции до persistNow и создания
  backup. Если другая запись успела между preflight и persist, сохраняется
  тип CatalogConflictError вместо общей ошибки.
- В маппинге появляется объяснение и две кнопки: продолжить в новой вкладке
  либо перейти в экспорт текущей памяти. Старый каталог/токен не перезаписываются.
- Кнопка продолжения открывает ту же страницу с #export (не запускает
  автоматический экономический расчёт), загружает актуальную БД обычным boot
  и открывает сохранённую исходную таблицу. Переносятся маппинг, режим/ключ и
  переключатели импорта, а также ограниченный whitelist настроек обогащения.
  Экономика при импорте по-прежнему отключена.
- Автоматического Apply нет: пользователь проверяет маппинг и нажимает кнопку.
  Несохранённые правки старой вкладки НЕ сливаются автоматически с диском.
  Старая вкладка и её S.pending остаются доступны для экспорта/сверки.
- Дескриптор содержит sourceId и конфигурацию, но не строки каталога, тело
  файла, API-токены или все S.settings. Используется копия sessionStorage,
  создаваемая браузером при window.open без noopener; родитель удаляет свою
  запись сразу. Дочерняя страница после чтения удаляет запись, параметр URL
  и opener. Срок дескриптора — час. Ошибки sessionStorage/popup/missing source
  не разрешают запись и не закрывают старую вкладку. При запрете копирования
  sessionStorage можно открыть источник через «Источники браузера» вручную.
- Если программный импорт не имеет сохранённого sourceId, продолжение сообщает
  о ручном выборе источника/файла, а не сериализует огромный массив в URL/storage.
- В диагностике конфликта есть ожидаемый/текущий токены ревизии и время; это не
  разрешение принять новую ревизию. Все freshness/undo/межвкладочные guards
  сохранены. SQL-импорт и SQLite storage path не менялись.

## Проверки

- Новый реальный Chromium tests/browser-import-conflict-e2e.js: две вкладки
  одной БД; новая сохраняет cost=77, старая сохраняет только в RAM cost=99 и
  пытается применить файл. Apply блокируется без checkpoint и изменения диска.
  Новая вкладка по кнопке восстанавливает тот же источник, маппинг, ключ и
  переключатели, применяет имя товара, сохраняя cost=77. Старая остаётся с
  cost=99, исходным pending и исходным токеном. Проверен blocked-popup path.
- Node и console regression PASS, восемь IndexedDB/probe suites PASS.
  Checkpoint suite дополнен preflight-stale (0 persist calls/0 backup writes)
  и конфликтом между preflight и queued-save: оба сохраняют typed error.
- Chromium обычный полный Apply прайс→OE: 1000 и 30000 SKU PASS; для 30000
  также partial-write path. Первый прайс не обогащён, экономика остаётся pending,
  OE-хвост/переоткрытие проверены существующим тестом.
- Chromium CSV/XLSX download regression на 1000 SKU PASS.
- Новый multi-tab тест добавлен в CI. Python в этой итерации не менялся и
  повторно не запускался. Реальные 122930 SKU пользователя и его OE-граф не
  доступны: точная сессия/причина смены ревизии не установлены.

## Действия пользователя

В уже открытой старой версии НЕ очищать IndexedDB и НЕ обновлять единственную
вкладку с несохранённой копией. Сначала экспортировать её данные. Открыть
опубликованную новую версию отдельно, выбрать загруженную таблицу в источниках
и проверить маппинг. В версии 12.9.159 при повторном конфликте это можно сделать
кнопкой продолжения прямо под ошибкой. Закрыть другие активные редакторы/импорты,
но старую вкладку с уникальными правками держать до проверки экспорта.
