# v12.9.62 — скорость кроссов, справочный режим импорта, файл категорий и ТН ВЭД

## 1. Накопление OE без O(n²)

Раньше каждая строка файла кроссов заново разбирала уже собранный список OE
(`mergeCodeLists(p.oe_numbers, val)` → `codeList()` по всей строке). Для артикула
с 3 838 OE это O(n²).

Теперь список собирается в накопителе: исходный разбирается **один раз на SKU**,
каждый новый код дописывается к строке.

| Сценарий | v12.9.61 | v12.9.62 |
|---|---|---|
| 3 837 строк одного артикула (PPK10207), этап «строки файла» | 12 795 мс | < 700 мс |
| тот же тест, весь импорт | 13 217 мс | **674 мс** (×19) |
| полный `Кроссы.csv` (486 692 строки), «строки файла» | 71,8 с | **14,3 с** (−80 %) |
| полный `Кроссы.csv`, весь импорт | 255 с | **155,8 с** |

Результат идентичен прежнему: тот же список OE, тот же порядок, тот же разделитель.

## 2. Справочный файл больше не создаёт новых SKU

Переключатель в мастере импорта: **«Справочный файл: только обогащать, новых SKU
не создавать»** (`#impEnrichOnly`, настройка `S.settings.importEnrichOnly`), по умолчанию включён.

Если в файле нет колонок цены, себестоимости и остатка, он считается справочным:
строки, которых нет среди SKU каталога, не создаются, счётчик пропущенных пишется в журнал
(`справочный файл: N строк без SKU в каталоге — новые не создавались`).
Файлы с ценой/себестоимостью/остатком создают новые SKU всегда.

Эффект на сегодняшних файлах при включённом режиме: каталог остаётся 122 930 SKU,
фантомных строк без цены — 0 вместо 81 525.
