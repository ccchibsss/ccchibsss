# v12.9.117 — Выгрузка OZON на движке, этап 3

Продолжение этапов 1–2. Справочные данные приложения вынесены в файлы
движка (не код): engine/ozon_template.json — 4 служебные строки
официального шаблона; engine/std_dims.json — словарь стандартных ОВХ
приложения (1789 записей). package_portable.bat копирует оба файла;
без них движок честно работает без шаблона/стандартов.

## Что сделано

- Пары «категория → тип»: таблица ozon_pairs, POST /ozon/pairs/import.
  Приложение перед выгрузкой отправляет entries() загруженного дерева
  Ozon (если есть). ozon_row: единственный тип категории подставляется;
  тип без категории дополняется категорией при однозначности; пара не
  из справочника — ошибка в колонке «Ошибка». Без справочника поведение
  этапов 1–2 (тип как есть из синка).
- Стандартные ОВХ при экспорте: только ТОЧНОЕ нормализованное совпадение
  (категория, затем название) со словарём, одна подпись значений —
  заполняются только пустые поля, реальные данные не перетираются.
  Заполненное помечается «СТАНДАРТ (не измерено)» в «Недочётах» и жёлтой
  заливкой ячеек в XLSX (стили stdlib-писателя).
- Официальный XLSX: 4 служебные строки шаблона (группы, шапка,
  обязательность, подсказки), данные с 5-й строки.
- ЧЗ по списку ТН ВЭД: параметр chz (GET, коды через запятую) / chz_codes
  (POST) — совпадение по префиксу кода ТН ВЭД ставит «Нужен код
  маркировки» = Да (если пусто) и пометку в «Недочётах».

## Проверки

- unittest TestOzonStage3: стандарт «Распредвал» 50×10×10 см/4 кг
  заполнил пустые ОВХ (4000 г, мм отсортированы), реальные данные не
  тронуты; пара подставила тип и отклонила чужой; ЧЗ по префиксу 8708;
  шаблон 4×46 и XLSX со styles.xml. Движок 36/36.
- Живой цикл: импорт пары → карточка без типа и ОВХ → XLSX: служебные
  строки на месте, тип подставлен, «Да» маркировки по ЧЗ 8483,
  жёлтая заливка применена.

## Что не портировано (осознанно)

- Fuzzy/contains-сопоставление StdDims.match(review) и ручное
  подтверждение совпадений: на движке только точные совпадения —
  неоднозначные стандарты в выгрузку не подмешиваются.
- Liquid-шаблоны аннотаций и rich-контента: поле description/rich_content
  по-прежнему уходит как есть из синка приложения.
- Словарь типов Seller API целиком в репозиторий не вносится: пары
  приходят из приложения в рантайме (дерево Ozon у пользователя свежее).
