# Данные

Сами файлы в проект не кладём (прайс — 22 МБ); здесь структура и статистика.

## Прайс поставщика (основной)
- Файл: `export_Moskow_RUB_RS73404.csv` (имя может меняться), CP1251, ~22 МБ.
- Строк: **124 459** (+ заголовок). Дубли артикул+бренд: 0.
- Колонки: Бренд; Каталожный номер; Описание; Остаток; Кратность; Валюта;
  Цена; Штрихкод; ТН ВЭД; 2 колонки сертификата.
- Валюта везде RUB; пустых ключевых полей нет; артикулов с несколькими
  брендами — 510. Себестоимости и весогабаритов в прайсе нет.

## Кросс-листы
- Файл: `Кросс листы.csv`, CP1251, ~1,3 МБ. Строк: **42 740**.
- Колонки: Артикул; Бренд; OE.
- Уникальных пар артикул+бренд: 20 543. Уникальных OE: 38 112.
- В прайсе по артикул+бренд находится только **12,2%** пар кроссов;
  неоднозначных OE (несколько пар) — 3 638 (такие OE для поиска не годятся).

## Экспорты приложения
- Полный каталог: 201 колонка + пользовательские; лёгкий экспорт XLSX с
  калькулятором («Вводы и ставки»), v12.9.79–82.
- Комплект повторной загрузки (v12.9.89–90): все загруженные столбцы
  значениями, без расчётных полей — «круг» файл → приложение → файл.
- Проверочный старый экспорт: `UC_unit_economics_OZON_2026-11-06_*.csv`
  (12 SKU) в корне репозитория.
- SKU, посчитанные по стандартным ОВХ, в выгрузке подсвечиваются #FFA07A и
  имеют колонку-маркер «ОВХ из стандартных при расчёте».

## Хранилища приложения (браузер)
- IndexedDB (Dexie): `products` — каталог в «тонком» виде (~0,45 КБ/SKU),
  `products_stage` — черновик чанковой записи, реестры Каталога V
  (OE/связки/кроссы/цены) — отдельными таблицами.
- Память вкладки: рабочий каталог `S.rows`; с посчитанной экономикой
  ~1,6 КБ/SKU. Каталог на диске после дискового импорта поднимается в память
  один раз, как при старте приложения.
