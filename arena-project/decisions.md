# Решения из чата (не переизобретать)

1. **Обогащение — только по двум ключам**: артикул+бренд и уникальный
   OE-номер. Прямое указание владельца: «Без поиска по аналогу. Только
   sku+бренд или OE номеру» (v12.9.85; аналог-индекс удалён).
2. **Первый файл — прайс**: он задаёт состав каталога; последующие файлы
   только обогащают SKU прайса и не расширяют каталог (v12.9.83).
3. **Стандартные ОВХ в каталог не пишутся** (с v12.9.67, `StdDims.fill`
   отключён). Применяются: временно при расчёте (v12.9.91, только exact и
   пустые поля, с пометкой) и при выгрузке (подсветка #FFA07A, v12.9.92).
4. **Лёгкий импорт**: экономика считается при экспорте/входе в расчётные
   разделы, а не при загрузке (v12.9.86–88). После экспорта расчётные поля
   сбрасываются.
5. **Дисковый импорт** — отдельный режим для пары прайс+кроссы (v12.9.93):
   поток в IndexedDB, полная замена, авто-маппинг. Обычный импорт с ручным
   маппингом и дозагрузкой остаётся основным для нестандартных файлов.
6. **Карантин важнее экспорта**: заблокированные по аномалиям SKU не
   выгружаются; «молчаливые» потери проверяются счётчиком заблокированных.
7. **Слияния PR — только по прямому указанию владельца** («Please merge the
   pull request»). PR #20–#39 смержены так; PR #28 закрыт без слияния.
8. **Воркер для экономики отложен**: перенос `computeEconomics` требует
   паритетных тестов на цифрах прибыли. Вместо него — пропуск пересчёта при
   неизменных параметрах (v12.9.94, п.7).
